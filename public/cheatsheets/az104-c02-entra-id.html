Lesson 20 · 4.1

What is Microsoft Entra ID

Το Microsoft Entra ID (πρώην Azure Active Directory / AAD) είναι cloud-based Identity and Access Management (IAM) service. Δεν είναι Active Directory Domain Services (ADDS) — είναι fundamentally διαφορετική υπηρεσία.

Entra ID vs Active Directory Domain Services

Entra ID (Cloud)Active Directory DS (On-prem)
ProtocolOAuth2, OpenID Connect, SAML, WS-FedKerberos, NTLM, LDAP
StructureFlat — users, groups, tenantsHierarchical — OUs, forests, domains
Join typeAzure AD Join, Hybrid Join, RegistrationDomain Join (scl.local κλπ)
Group Policy❌ (χρησιμοποιείς Intune MDM/MAM)✅ GPO full support
AuthenticationCloud-native, MFA, Conditional AccessOn-premises only (χωρίς ADFS/PTA)
BillingFree / P1 / P2 per user/monthIncluded σε Windows Server license
ℹ️
Για Septona: Έχεις on-prem AD (scl.local domain) synced με Azure via Entra Connect (Azure AD Connect). Αυτό λέγεται Hybrid Identity — users υπάρχουν on-prem και sync-άρονται στο cloud. Passwords managed on-prem, group policies από AD DS, αλλά cloud apps authenticating μέσω Entra ID.

Entra ID Concepts

  • Tenant: Dedicated instance του Entra ID για ένα organization. Κάθε tenant έχει δικό του domain (*.onmicrosoft.com) ή custom domain.
  • Directory: Το repository των identities — users, groups, apps, devices
  • Subscription trust: Κάθε Azure subscription "εμπιστεύεται" έναν Entra ID tenant — οι users/groups εκεί μπορούν να λάβουν RBAC roles στο subscription
  • Object: Κάθε entity στο Entra ID (user, group, device, app, SP) έχει unique Object ID
# Get current Entra ID tenant info με CLI
az account show --query "{TenantId:tenantId, SubscriptionId:id}"

# List all users στο tenant
az ad user list --output table

# Get tenant details
az rest --method get --url "https://graph.microsoft.com/v1.0/organization"

Lesson 21 · 4.2

Microsoft Entra ID Free vs P1 vs P2

Κρίσιμη γνώση για το exam — πολύ συχνή ερώτηση. Ποιο feature απαιτεί ποιο license tier;

Free (included)
  • User & Group management
  • Basic MFA (per-user)
  • SSO σε Office 365 apps
  • B2B collaboration (guests)
  • Azure AD Connect sync
  • Self-service password change
  • Security reports
P1 (~€6/user/month)
  • Conditional Access
  • Dynamic Groups
  • Hybrid identity (Entra Connect)
  • Azure AD Join + MDM auto-enroll
  • Group-based licensing
  • SSPR (password writeback)
  • Microsoft Identity Manager
  • Cloud App Discovery
P2 (~€9/user/month)
  • PIM (Privileged Identity Mgmt)
  • Identity Protection
  • Access Reviews
  • Entitlement Management
  • Risk-based Conditional Access
  • Risky users/sign-ins detection
  • Includes all P1 features
🎯
Exam Must-Know:
• Conditional Access → P1 minimum
• Dynamic Groups → P1 minimum
• PIM (Privileged Identity Management) → P2 minimum
• Identity Protection → P2 minimum
• Basic MFA → Free (per-user legacy) ή Security Defaults (free)
• SSPR με password writeback → P1 minimum

Microsoft 365 License Bundles

Συχνά δεν αγοράζεις Entra P1/P2 ξεχωριστά — περιέχεται σε M365 bundles:

BundleEntra Tier included
Microsoft 365 Business Basic / StandardEntra ID Free
Microsoft 365 Business PremiumEntra ID P1
Microsoft 365 E3Entra ID P1
Microsoft 365 E5Entra ID P2
Azure AD Premium P2 standaloneEntra ID P2

Lessons 22–25 · 4.3

Managing Multiple Directories & Tenants

Μια εταιρεία μπορεί να έχει πολλαπλά Entra ID tenants — για λόγους compliance, M&A, ξεχωριστά environments (Dev/Prod).

Switch Between Tenants

  • Portal: Πάνω δεξιά → Settings (γρανάζι) → Directories → Switch directory
  • Κάθε tenant έχει το δικό του Tenant ID (GUID)
  • Ο ίδιος user account μπορεί να έχει access σε πολλαπλά tenants ως Guest
ℹ️
Septona Multi-Tenant: GR tenant (septona.gr) και BG tenant (septona.bg) είναι δύο ξεχωριστοί Entra ID tenants. Για cross-tenant access, χρησιμοποιείς B2B (external users) ή Azure Lighthouse (service provider scenarios).

Custom Domains

Κάθε tenant έρχεται με company.onmicrosoft.com. Μπορείς να προσθέσεις custom domain (π.χ. septona.gr):

  1. Entra ID → Custom domain names → Add custom domain
  2. Azure σου δίνει TXT record να βάλεις στο DNS
  3. Verify → domain γίνεται "Verified"
  4. Τώρα users μπορούν να έχουν UPN user@septona.gr

Manage Users

Τρεις κατηγορίες users στο Entra ID — σημαντικό να ξέρεις τη διαφορά για το exam:

User Types

TypeSourceManagedUPN Example
Cloud User Cloud-onlyΔημιουργείται απευθείας στο Entra IDEntra ID portal / PowerShell / CLIjohn@septona.gr
Synced User HybridOn-premises AD, synced via Entra ConnectOn-prem AD (changes sync-άρονται)john@septona.gr (same)
Guest User (B2B) ExternalExternal organization / personal emailInvited user manages own passwordjohn_contoso.com#EXT#@septona.gr
🎯
Synced Users: Δεν μπορείς να αλλάξεις password ή certain attributes για synced users απευθείας στο Entra ID portal — εμφανίζεται greyed out. Πρέπει να αλλάξεις on-premises στο AD, και η αλλαγή sync-άρεται μέσω Entra Connect (default: κάθε 30 λεπτά).

User Attributes

  • UPN (User Principal Name): Login identity — user@domain.com
  • Display Name: Εμφανιζόμενο όνομα
  • Object ID: Unique GUID — χρησιμοποιείται σε RBAC, scripts
  • Job Title, Department: Attributes — χρησιμοποιούνται σε dynamic group rules
  • Usage Location: Απαιτείται για license assignment
  • Account enabled: Enable/disable login χωρίς διαγραφή

Create User — CLI

# Create cloud user
az ad user create \
  --display-name "Kostas Papadopoulos" \
  --user-principal-name "kpapadopoulos@septona.gr" \
  --password "TempPass#2026!" \
  --force-change-password-next-sign-in true

# Get user info
az ad user show --id "kpapadopoulos@septona.gr"

# Update user (e.g. job title)
az ad user update \
  --id "kpapadopoulos@septona.gr" \
  --job-title "IT Support Specialist"

# Disable user account
az ad user update \
  --id "kpapadopoulos@septona.gr" \
  --account-enabled false
Realistic ScenarioNew Employee Onboarding — Septona

Κατάσταση: Νέος υπάλληλος ξεκινά στο BG site (Sofia). Χρειάζεται M365 account, access σε SharePoint, Microsoft Teams, και VPN για Azure resources.

  1. Δημιουργία user στο Entra ID: employee@septona.bg, Usage Location: BG
  2. Assign license: Microsoft 365 Business Premium (includes Teams, Exchange, Entra P1)
  3. Add σε groups: GRP-AllEmployees, GRP-BG-Office
  4. Assign Azure RBAC role αν χρειάζεται Azure portal access (Ch03)
  5. Enable MFA (Security Defaults ή Conditional Access policy)
  6. Send Temporary Access Pass (TAP) για passwordless first login

Lesson 31 · 5.2

Manage Groups

Groups χρησιμοποιούνται για bulk license assignment, RBAC, app access, Conditional Access. Δύο κύριοι τύποι:

Group Types

Security Group

  • Για RBAC resource access
  • Για Conditional Access
  • Για license assignment
  • Members: users, devices, service principals, other groups

Microsoft 365 Group

  • Για collaboration
  • Έχει mailbox, SharePoint, Teams
  • Members: users only
  • External members allowed

Membership Types

TypeΠώς λειτουργείLicense
Assigned DefaultAdmin προσθέτει/αφαιρεί members manuallyFree
Dynamic User P1 RequiredΑυτόματη προσθήκη/αφαίρεση βάσει user attribute rulesP1 minimum
Dynamic Device P1 RequiredΑυτόματη προσθήκη devices βάσει device attributesP1 minimum

Dynamic Group Rules

Dynamic groups χρησιμοποιούν membership rule syntax — query language βασισμένο σε user/device attributes:

# Dynamic rule: όλοι οι users του IT department στη Ελλάδα
(user.department -eq "IT") -and (user.country -eq "GR")

# Dynamic rule: όλοι οι full-time employees (not contractors)
(user.employeeType -eq "Employee")

# Dynamic rule: users με specific license
(user.assignedPlans -any assignedPlan.servicePlanId -eq "EXCHANGE_S_STANDARD")

# Create dynamic group με CLI
az ad group create \
  --display-name "DYN-IT-Greece" \
  --mail-nickname "DYN-IT-Greece"
# Membership rule set via portal ή MS Graph API
🎯
Dynamic Groups Delay: Όταν user attribute αλλάζει (π.χ. department), δεν προστίθεται άμεσα στο dynamic group. Ο sync μπορεί να πάρει έως 24 ώρες. Αν χρειάζεσαι instant membership, χρησιμοποίησε Assigned groups.

Manage Licenses

License assignment μπορεί να γίνει per user ή μέσω Group-based licensing (P1 required).

License Assignment Methods

MethodΠώςBest For
Direct AssignmentΈνας user την φορά — portal ή PowerShellΛίγοι users, exceptions
Group-based P1Assign license σε group → όλα τα members παίρνουν licenseLarge scale, automation
PowerShell / CLIBulk assignment μέσω scriptsMigrations, bulk changes
⚠️
Usage Location: Πριν assign license, ο user πρέπει να έχει Usage Location set. Αν δεν έχει, το license assignment αποτυγχάνει. Αυτό είναι πολύ συχνό πρόβλημα στο onboarding.
# PowerShell — Assign M365 Business Premium license σε user
$user = Get-AzureADUser -ObjectId "user@septona.gr"

# Set usage location πρώτα
Set-AzureADUser -ObjectId $user.ObjectId -UsageLocation "GR"

# Get available license SKUs
Get-AzureADSubscribedSku | Select-Object SkuPartNumber, ConsumedUnits

Lesson 33 · 5.4

Administrative Units (AUs)

Τα Administrative Units επιτρέπουν να περιορίσεις το scope ενός admin role. Αντί ένας Helpdesk admin να έχει reset password για ΟΛΟΥΣ τους users, μπορεί να έχει scope μόνο στο AU "Greece-Office".

Administrative Units — Use Case

Tenant (septona.gr)
  ├── AU: Greece-Office
  │    ├── Users: GR employees
  │    └── Admin: help_gr@septona.gr (User Administrator — scoped)
  └── AU: Bulgaria-Office
       ├── Users: BG employees
       └── Admin: help_bg@septona.gr (User Administrator — scoped)

  • Κάθε AU μπορεί να περιέχει users, groups, devices
  • Εκχωρείς admin roles σε AU scope (όχι tenant-wide)
  • AUs δεν κληρονομούνται — δεν υπάρχουν nested AUs
  • Requires Entra ID P1 ή P2

Lesson 35 · 5.6

Bulk Operations

Για μαζικές δημιουργίες/αλλαγές users, το Entra ID υποστηρίζει CSV-based bulk operations μέσω portal ή PowerShell.

Portal Bulk Operations

  • Bulk create users: Upload CSV με columns: Name, User name, Initial password, Block sign in
  • Bulk invite users: CSV με email addresses για B2B invitations
  • Bulk delete users: CSV με Object IDs ή UPNs

PowerShell Bulk Import

# Bulk user creation από CSV
$users = Import-Csv "new-employees.csv"

foreach ($u in $users) {
  New-MgUser `
    -DisplayName $u.DisplayName `
    -UserPrincipalName $u.UPN `
    -PasswordProfile @{
      Password = $u.TempPassword
      ForceChangePasswordNextSignIn = $true
    } `
    -AccountEnabled $true `
    -UsageLocation $u.Country
    
  Write-Host "Created: $($u.UPN)"
}

External Users (B2B Collaboration)

Το Azure AD B2B (Business-to-Business) επιτρέπει σε external users να κάνουν access σε resources του tenant σου χρησιμοποιώντας τα δικά τους credentials.

B2B Invitation Flow

  1. Admin στο Septona tenant invites partner@externalcompany.com
  2. External user λαμβάνει email invitation
  3. User κάνει accept — δημιουργείται Guest object στο Septona tenant
  4. Guest user μπορεί να access Azure resources (βάσει RBAC) ή M365 apps (βάσει licenses)
  5. User authenticates με δικά του credentials (external IdP ή Microsoft account)
ΧαρακτηριστικόGuest UserMember User
UPN formatemail_domain#EXT#@yourtenant.onmicrosoft.comuser@yourdomain.com
Password managed byExternal IdP (δικός τους)Your tenant
License requiredFree (B2B up to 5× your paid users)Paid license per user
Default permissionsRestricted (cannot read all directory)Full member access to directory

az ad invitation create \
  --invited-user-email-address "partner@cosmoprof.com" \
  --invite-redirect-url "https://myapps.microsoft.com" \
  --send-invitation-message true

Lesson 37 · 5.8

Self-Service Password Reset (SSPR)

Το SSPR επιτρέπει σε users να reset-άρουν το password χωρίς να χρειαστούν helpdesk. Μειώνει δραματικά το support ticket volume.

SSPR Configuration

SettingOptionsNotes
Enabled forNone / Selected (group) / AllBest practice: pilot σε group πρώτα
Authentication methodsMobile app notification, Email, Phone, Security questionsMinimum 1 method required
Number of methods required1 ή 22 methods = more secure
Password writeback P1Enabled / DisabledSyncs reset password back to on-prem AD
RegistrationRequire at login / Combined registrationΠρέπει users να κάνουν register methods πρώτα
🎯
SSPR & Password Writeback: Αν έχεις hybrid users (synced από on-prem AD), και user κάνει SSPR στο cloud, το νέο password πρέπει να γραφεί πίσω στο on-prem AD. Αυτό λέγεται Password Writeback και απαιτεί Entra ID P1. Χωρίς writeback, synced users δεν μπορούν να χρησιμοποιήσουν SSPR.
Realistic ScenarioSSPR Rollout — Septona MFA Project

Κατάσταση: Πρόβλημα: Helpdesk δέχεται 15–20 password reset requests/εβδομάδα. Θέλουμε να μειώσουμε αυτό στο μηδέν. Έχουμε M365 Business Premium (Entra P1).

  1. Entra ID → Password reset → Properties → Enable for: Selected group → GRP-SSPR-Pilot (20 users αρχικά)
  2. Authentication methods: Email + Mobile app code (2 methods required)
  3. Enable Password Writeback (Entra P1 ✓)
  4. Require registration at next login για members του pilot group
  5. Monitor: Admin → SSPR Usage report — 2 εβδομάδες pilot
  6. Αν OK → change SSPR to All users

Αποτέλεσμα: Users reset passwords μόνοι τους 24/7, helpdesk tickets μειώνονται 85%.

Chapter 02

Quiz — Entra ID, Users & Groups

◈ Question 01
Θέλεις να δημιουργήσεις group που να προσθέτει αυτόματα users όταν το job title γίνει "Manager". Ποιο feature χρειάζεσαι;
  • A) Assigned Group — Free tier
  • B) Dynamic User Group — Entra P1
  • C) Dynamic Device Group — Entra P1
  • D) Microsoft 365 Group — Free tier
✅ B — Dynamic User Group, Entra P1. Dynamic groups βασίζονται σε user attributes (job title, department, κλπ). Απαιτούν Entra P1 minimum. Assigned Group = manual management. Dynamic Device = για devices, όχι users.
◈ Question 02
Προσπαθείς να αλλάξεις το password ενός user απευθείας από το Entra ID portal αλλά το option είναι greyed out. Ποια η πιθανότερη αιτία;
  • A) Ο user έχει MFA enabled
  • B) Δεν έχεις Global Administrator role
  • C) Ο user είναι synced από on-premises AD
  • D) Ο user account είναι disabled
✅ C — Synced user. Synced users διαχειρίζονται on-premises. Password changes και certain attributes πρέπει να γίνουν στο on-prem AD. Το Entra ID portal τα εμφανίζει ως read-only για synced attributes.
◈ Question 03
Ποιο minimum Entra ID tier απαιτείται για Conditional Access policies;
  • A) Entra ID Free
  • B) Entra ID P1
  • C) Entra ID P2
  • D) Microsoft 365 E5
✅ B — Entra ID P1. Conditional Access ξεκινά από P1. PIM και Identity Protection απαιτούν P2. Free tier έχει Security Defaults (predefined policies) αλλά όχι customizable Conditional Access.
◈ Question 04
Hybrid user (synced από on-prem AD) κάνει SSPR στο cloud αλλά δεν μπορεί να κάνει login on-premises με το νέο password. Τι λείπει;
  • A) Δεν έχει Entra P2 license
  • B) Password Writeback δεν είναι enabled στο Entra Connect
  • C) Ο user δεν έχει registered SSPR methods
  • D) Το on-prem AD δεν υποστηρίζει SSPR
✅ B — Password Writeback. Χωρίς password writeback, νέο password από cloud SSPR δεν γράφεται πίσω στο on-prem AD. Απαιτεί Entra P1 (όχι P2) και να είναι configured στο Entra Connect. Ο user μπορεί να κάνει login cloud apps αλλά όχι on-prem.
◈ Question 05
Θέλεις Helpdesk admin να μπορεί να reset passwords ΜΟΝΟ για users του Greece office, όχι για όλο τον tenant. Ποια feature χρησιμοποιείς;
  • A) Custom RBAC role με scope στο Resource Group
  • B) Administrative Unit με scoped User Administrator role
  • C) Conditional Access policy
  • D) Dynamic group με Greece users
✅ B — Administrative Unit. AUs επιτρέπουν να scope-άρεις Entra ID admin roles (όπως User Administrator) σε subset των users/groups. Helpdesk admin μπορεί να reset passwords μόνο για users που ανήκουν στο AU "Greece". RBAC είναι για Azure resources, όχι Entra ID user management.

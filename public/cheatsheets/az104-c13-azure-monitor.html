Lesson 161 · 23.1

Azure Monitor Overview

Metrics vs Logs

MetricsLogs
TypeNumerical time-seriesStructured/unstructured records
CollectionAutomatic (most resources)Requires Diagnostic Settings / agent
Retention93 days defaultConfigurable (30–730 days in LAW)
QueryMetrics ExplorerLog Analytics (KQL)
ExamplesCPU%, Disk IOPS, HTTP requests/sActivity log, VM events, App traces
AlertingMetric alerts (near real-time)Log query alerts (scheduled)

Azure Monitor Data Sources

  • Activity Log: Control-plane events (WHO did WHAT WHEN). Subscription-level. 90-day retention. Free.
  • Resource Logs (Diagnostics): Data-plane operations. Must enable via Diagnostic Settings.
  • VM Guest Metrics: Requires Azure Monitor Agent (AMA) or Log Analytics agent.
  • Application Insights: APM — application traces, requests, exceptions, dependencies.
🎯
Activity Log: Free, 90 days, cannot disable. Shows control-plane (management) operations: "Who deleted this VM? Who changed this NSG rule?" For data-plane events (what happened INSIDE the resource), use Diagnostic Settings.
⚙️
Lesson 162 · 23.2

Diagnostic Settings

Diagnostic Settings = enable collection of resource logs and metrics, and route them to destinations.

Destinations

  • Log Analytics Workspace: Query with KQL. Best for analysis and alerting.
  • Storage Account: Long-term archival. Cost-effective for compliance.
  • Event Hub: Stream to SIEM (Splunk, Microsoft Sentinel).
  • Partner Solutions: Datadog, Elastic, etc.
# Enable diagnostic settings for VM — send to Log Analytics
az monitor diagnostic-settings create \
  --name VMDiagnostics \
  --resource /subscriptions/.../VMs/SRV-APP-GR-01 \
  --workspace /subscriptions/.../workspaces/LAW-Septona \
  --logs '[{"category":"Administrative","enabled":true}]' \
  --metrics '[{"category":"AllMetrics","enabled":true}]'
💡
Not automatic: Resource logs require Diagnostic Settings to be explicitly enabled. Each resource has its own settings. Azure Policy can enforce "DeployIfNotExists" to auto-configure Diagnostic Settings on new resources.
🖥️
Lesson 163 · 23.3

VM Insights

VM Insights = pre-packaged monitoring for VMs. Provides Performance and Map views. Requires Azure Monitor Agent (AMA) on the VM.

  • Performance tab: CPU, memory, disk, network charts over time
  • Map tab: Visual dependency map — shows what processes/ports the VM uses and what it connects to
  • Enables via: VM → Insights → Enable (installs AMA + DCR)
  • Data goes to Log Analytics Workspace
✅
AMA vs Legacy MMA: Azure Monitor Agent (AMA) is the current agent — replaces the legacy Log Analytics agent (MMA/OMS). AMA uses Data Collection Rules (DCR). For AZ-104 exam: AMA is the recommended approach.
🔍

Log Analytics & KQL

Log Analytics Workspace (LAW) = central repository for log data. Query with KQL (Kusto Query Language).

Essential KQL Operators

// Filter records Heartbeat | where TimeGenerated > ago(1h) | where Computer contains "SRV-APP" // Count VMs by OS Heartbeat | summarize count() by OSType // Top 10 VMs by CPU Perf | where CounterName == "% Processor Time" | summarize avg_cpu=avg(CounterValue) by Computer | top 10 by avg_cpu desc // Failed logins last 24h SecurityEvent | where TimeGenerated > ago(24h) | where EventID == 4625 // Failed logon | project TimeGenerated, Computer, Account, IpAddress | order by TimeGenerated desc // Chart - render as timechart Perf | where CounterName == "% Processor Time" | summarize avg(CounterValue) by bin(TimeGenerated, 5m), Computer | render timechart

Alerts & Action Groups

Alert Components

  • Scope: What to monitor (subscription, RG, specific resource)
  • Condition: When to fire (metric threshold, log query result, activity log event)
  • Action Group: What to do when fired
  • Severity: 0 (Critical) to 4 (Verbose)

Action Group Actions

  • Email/SMS/Push/Voice: Notify people
  • Azure Function: Auto-remediation
  • Logic App: Complex workflows
  • Webhook: Call external systems (PagerDuty, ServiceNow)
  • ITSM: Create tickets in ServiceNow, etc.
# Create metric alert — CPU > 80% for 5min
az monitor metrics alert create \
  --name Alert-HighCPU-SRV-APP \
  --resource-group RG-Servers-GR \
  --scopes /subscriptions/.../VMs/SRV-APP-GR-01 \
  --condition "avg Percentage CPU > 80" \
  --window-size 5m \
  --evaluation-frequency 1m \
  --severity 2 \
  --action /subscriptions/.../actionGroups/IT-Alerts
Realistic ScenarioSeptona IT Monitoring Setup

Goal: Alert IT team when production VMs have high CPU, disk full, or service failure.

  1. Create Log Analytics Workspace: LAW-Septona-Production
  2. Enable VM Insights on all production VMs (installs AMA)
  3. Diagnostic Settings: Activity Log → LAW-Septona
  4. Create Action Group: AG-IT-Alerts → Email: vag@septona.gr, SMS: +30...
  5. Alert 1: CPU > 90% for 10 min → Severity 1 → AG-IT-Alerts
  6. Alert 2: Disk free < 10% → Severity 2 → AG-IT-Alerts
  7. KQL scheduled alert: Failed logins > 10 in 1h → Severity 0 (Critical)

Quiz

◈ Q01
Θέλεις να δεις ποιος admin διέγραψε ένα Resource Group χθες. Που το βρίσκεις;
  • A) Azure Monitor Metrics
  • B) Activity Log
  • C) VM Insights
  • D) Resource Logs
✅ B — Activity Log. Activity Log = control-plane events (WHO did WHAT WHEN). WHO deleted resource group = control-plane action. Free, 90-day retention. Resource Logs = data-plane. Metrics = numbers, not events.
◈ Q02
KQL query: θέλεις average CPU για κάθε VM τελευταία ώρα. Ποιο operator aggregates;
  • A) where
  • B) project
  • C) summarize
  • D) extend
✅ C — summarize. summarize avg(CounterValue) by Computer — summarize performs aggregations (avg, count, sum, max, min). where = filter. project = select columns. extend = add column.
◈ Q03
Resource Logs (Diagnostics) από VM αποστέλλονται αυτόματα στο Log Analytics;
  • A) Ναι — αυτόματα για όλα τα resources
  • B) Ναι — μόνο για VMs
  • C) Όχι — απαιτείται Diagnostic Settings configuration
  • D) Ναι — αν VM Insights είναι enabled
✅ C — Requires Diagnostic Settings. Resource logs are NOT collected automatically. You must explicitly configure Diagnostic Settings for each resource (or use Azure Policy to auto-deploy). Only Activity Log and basic Metrics are collected automatically.

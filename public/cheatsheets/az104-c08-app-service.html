Create a Web App

Key settings when creating App Service:

  • Runtime stack: .NET 8, Node 20, Python 3.12, PHP 8.3, Java 17, Ruby, Docker
  • OS: Windows or Linux (affects available runtimes)
  • Region: Same as App Service Plan
  • App Service Plan: Choose existing or create new
  • Default URL: appname.azurewebsites.net
# Create App Service Plan + Web App
az appservice plan create   --name ASP-Septona-Production   --resource-group RG-Web-GR   --sku S2 --is-linux

az webapp create   --name septona-portal   --resource-group RG-Web-GR   --plan ASP-Septona-Production   --runtime "NODE:20-lts"

Deployment Slots & Swap

Deployment slots = separate environments (staging, testing) with their own hostname and settings. Requires Standard+ tier.

  • Each slot: unique URL appname-slotname.azurewebsites.net
  • Swap: Exchange slots instantly — zero downtime release
  • Sticky settings: "Slot settings" stay with slot during swap (e.g. ENVIRONMENT variable)
  • Auto-swap: Auto-swap staging → production on deploy (for CD)
  • Swap warms up new version in staging before routing traffic
# Create staging slot
az webapp deployment slot create   --name septona-portal   --resource-group RG-Web-GR   --slot staging

# Swap staging → production
az webapp deployment slot swap   --name septona-portal   --resource-group RG-Web-GR   --slot staging   --target-slot production
Realistic ScenarioZero-Downtime Release — Septona Portal

Flow: Dev deploys to staging slot → QA tests at staging URL → If OK, swap to production (instant, zero downtime). If problem → swap back.

  1. Deploy v2.0 to septona-portal-staging.azurewebsites.net
  2. QA team validates — all tests pass
  3. Swap slots → staging becomes production instantly
  4. Old production is now in staging slot — easy rollback if needed

Scaling

Scale Up (Vertical)

  • Change App Service Plan tier
  • More CPU, RAM, disk
  • Requires brief restart
  • Single instance

Scale Out (Horizontal)

  • Add more instances (copies)
  • Manual or Auto
  • No restart
  • Load balanced automatically

Auto Scale Rules

  • Based on CPU, memory, HTTP queue
  • Schedule-based
  • Min/Max instance count
  • Standard+ only

Custom Domain & TLS

Custom Domain Setup

  1. Buy domain or use existing (e.g. portal.septona.gr)
  2. Add CNAME: portal → septona-portal.azurewebsites.net (or A record with public IP)
  3. App Service → Custom Domains → Add custom domain → Verify DNS ownership (TXT record)
  4. Bind SSL certificate (managed free certificate or bring your own)
# Add custom domain
az webapp config hostname add   --webapp-name septona-portal   --resource-group RG-Web-GR   --hostname portal.septona.gr

# Create free managed certificate
az webapp config ssl create   --name septona-portal   --resource-group RG-Web-GR   --hostname portal.septona.gr

◈ Q01
Minimum App Service Plan tier για Deployment Slots;
  • A) Free (F1)
  • B) Basic (B1)
  • C) Standard (S1)
  • D) Premium (P1v3)
✅ C — Standard (S1). Deployment Slots available from Standard tier. Free/Basic = no slots.
◈ Q02
Κάνεις swap staging→production. Η ENVIRONMENT variable (sticky setting) πρέπει να παραμείνει "Staging" στο staging slot. Τι κάνεις;
  • A) Τίποτα — variables πάντα swap-άρονται
  • B) Ορίζεις ENVIRONMENT ως "Slot setting" — δεν swap-άρεται
  • C) Χρησιμοποιείς app.config file
  • D) Πρέπει να το αλλάξεις χειροκίνητα μετά το swap
✅ B — Slot setting. Variables marked as "Slot setting" stay with the slot during swap. Non-sticky settings swap with the app. Use sticky settings for environment-specific values like connection strings, API endpoints.

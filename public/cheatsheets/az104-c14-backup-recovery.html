Backup & Azure Site Recovery

Protect your data and ensure business continuity. Azure Backup provides point-in-time restore. Azure Site Recovery (ASR) provides disaster recovery with near-zero RPO. Know the difference: Backup = restore data. ASR = keep services running.

24.1

Recovery Services Vault (RSV)

The Recovery Services Vault is the central container for both Azure Backup and Azure Site Recovery data. Must exist in same region as protected resources (for backup — ASR uses secondary region).

  • One vault can protect VMs, SQL databases, file shares, on-premises servers
  • Backup redundancy: LRS (default), GRS, ZRS — set BEFORE first backup
  • GRS (recommended): Backup data replicated to secondary region — protects from region failure
  • Cross Region Restore: Enabled on GRS vaults — restore VM in secondary region
# Create Recovery Services Vault
az backup vault create \
  --name RSV-Septona-Production \
  --resource-group RG-Backup-GR \
  --location westeurope

# Set storage redundancy to GRS (before first backup)
az backup vault backup-properties set \
  --name RSV-Septona-Production \
  --resource-group RG-Backup-GR \
  --backup-storage-redundancy GeoRedundant

Azure Backup

VM Backup Components

  • Backup Policy: Schedule (daily/weekly) + retention rules (daily/weekly/monthly/yearly)
  • Recovery Points: Each backup creates a recovery point. Default: 180 daily points.
  • Instant Restore: Snapshots kept 1–5 days for fast restore (before moving to vault)
  • Application-consistent backup: VSS writer ensures app data consistency for Windows VMs
  • No agent needed for Azure VMs: Azure Backup extension handles it automatically
# Enable backup for VM
az backup protection enable-for-vm \
  --resource-group RG-Backup-GR \
  --vault-name RSV-Septona-Production \
  --vm /subscriptions/.../VMs/SRV-APP-GR-01 \
  --policy-name DefaultPolicy

# Trigger immediate backup
az backup protection backup-now \
  --resource-group RG-Backup-GR \
  --vault-name RSV-Septona-Production \
  --container-name IaasVMContainer;iaasvmcontainer... \
  --item-name SRV-APP-GR-01 \
  --backup-management-type AzureIaasVM

# List recovery points
az backup recoverypoint list \
  --resource-group RG-Backup-GR \
  --vault-name RSV-Septona-Production \
  --container-name SRV-APP-GR-01 \
  --item-name SRV-APP-GR-01 \
  --backup-management-type AzureIaasVM

File Recovery from VM Backup

File Recovery allows you to mount a VM backup as a network drive and copy specific files — without restoring the entire VM.

  1. RSV → Backup Items → Select VM → File Recovery
  2. Select recovery point (backup date/time)
  3. Download script (Python for Linux, PowerShell for Windows)
  4. Run script on target machine — mounts backup as drive letter
  5. Browse and copy needed files
  6. Unmount (script times out after 12 hours)
💡
12-hour limit: The mounted backup drive unmounts automatically after 12 hours. The script provides a command to unmount manually when done. Scripts are signed by Microsoft and expire — generate fresh for each session.

Lesson 170 · 24.4

On-Premises Backup (MARS Agent)

Microsoft Azure Recovery Services (MARS) Agent = backup on-premises Windows servers/files to Azure RSV.

MARS Agent

  • Files & folders only
  • System State
  • Windows only
  • Backup to RSV directly
  • Up to 3x/day

Azure Backup Server (MABS)

  • Files, folders, workloads
  • SQL, Exchange, SharePoint
  • Windows + Linux files
  • Local disk + RSV
  • More flexible

DPM (System Center)

  • Enterprise backup
  • Full workload protection
  • Complex setup
  • Existing SCDPM + Azure
  • Most features
💡
For Septona: On-prem file servers in GR office → MARS Agent → RSV in West Europe. Simple, no extra infrastructure. For full server workload backup including SQL → MABS on a dedicated server.

Lesson 173 · 24.5

Soft Delete

Soft Delete protects backup data from accidental or malicious deletion. When enabled, deleted backup data is retained for 14 additional days before permanent deletion.

  • Default: Enabled by default on new vaults
  • Retention: 14 days after deletion (data marked as "soft deleted")
  • Recovery: During 14-day window — "Undelete" to restore
  • Cost: No additional cost during soft delete retention period
  • Enhanced Soft Delete: Make it always-on (cannot disable) for extra security
🎯
Soft Delete exam fact: Default 14-day retention after soft delete. You can increase to up to 180 days. "Enhanced Soft Delete" is irreversible — once enabled, cannot be disabled. Protects against ransomware attacks on backups.

Azure Site Recovery (ASR)

Azure Site Recovery = Disaster Recovery as a Service. Continuously replicates VMs to a secondary region. In case of disaster → failover to secondary in minutes.

ASR vs Azure Backup

GoalRestore data (point-in-time)Keep services running (DR)

RTOHours (restore process)Minutes (failover)

Failover, Test Failover & Failback

OperationWhat it doesImpact
Test Failover SafeCreates test VM in isolated VNet — verifies DR readinessNo impact on production. Test and cleanup.
Failover (Planned)Graceful — replicates latest data, then switchesMinimal data loss. Used for planned maintenance.
Failover (Unplanned)Emergency — uses latest replica, accepts some data lossSmall data loss possible. Used during disaster.
CommitConfirms failover is complete — removes original VMNo rollback possible after commit
FailbackReplicates back to primary region after it's restoredReturns to normal operations
🎯
Test Failover is non-disruptive. Always run Test Failover periodically to validate your DR plan works. It creates a temporary VM in an isolated network — no impact on production or replication. Clean up after testing to avoid costs.
Realistic ScenarioDR Plan — Septona Production VMs

Setup: Primary: West Europe (GR/BG servers). DR: North Europe.

  1. Create RSV in North Europe
  2. Enable ASR for all production VMs → target: North Europe
  3. Configure Replication Policy: RPO 15 minutes, App-consistent snapshot every 4h
  4. Monthly: Run Test Failover → validate apps work in DR region → cleanup
  5. Disaster occurs: Failover (Unplanned) → VMs start in North Europe in ~15 min
  6. Primary restored: Failback to West Europe

RTO: ~15 minutes | RPO: ~15 minutes — much better than backup-only approach (RTO: hours).

Quiz — Backup & ASR

◈ Q01
Admin κατά λάθος διέγραψε backup item. Soft Delete enabled. Τι γίνεται;
  • A) Backup data χάθηκε αμέσως
  • B) Data κρατείται 14 ημέρες — μπορεί να ανακτηθεί
  • C) Data κρατείται 90 ημέρες
  • D) Backup συνεχίζει κανονικά χωρίς αλλαγή
✅ B — 14 days. Soft Delete retains deleted backup data for 14 additional days. During this window, admin can "Undelete" to restore. After 14 days, data is permanently deleted.
◈ Q02
Business απαιτεί: αν West Europe region πέσει, production VMs να είναι online σε <30 λεπτά. Ποια λύση;
  • A) Azure Backup με GRS vault
  • B) Azure Backup με daily backups
  • C) Azure Site Recovery
  • D) Manual VM snapshots
✅ C — Azure Site Recovery. ASR = continuous replication + failover in minutes. RTO <30min. Azure Backup restores take hours (image download, VM creation). Snapshots = manual, no automation. ASR is designed specifically for this scenario.
◈ Q03
Ποια ASR operation ελέγχεις DR readiness χωρίς να επηρεάσεις production;
  • A) Planned Failover
  • B) Unplanned Failover
  • C) Test Failover
  • D) Commit
✅ C — Test Failover. Creates a temporary VM in an isolated test VNet — no impact on production or ongoing replication. Validates that your DR plan works. Always clean up after test to avoid unnecessary costs.

Lesson 122 · 16.1

Container Fundamentals

Containers = lightweight, portable runtime environments. Same image runs identically everywhere. Faster than VMs (no OS overhead).

ServiceDescriptionUse Case
ACIServerless containers — no infrastructure managementSimple tasks, burst, dev/test
Azure Container AppsManaged platform (on K8s) with KEDA autoscalingMicroservices, event-driven
AKSFull managed KubernetesComplex production orchestration
App Service (Containers)PaaS web hosting for containersWeb apps in containers
ACRPrivate Docker registryStore and manage container images
🎯
Quick Decision: Simple task / burst = ACI. Microservices with scale-to-zero = Container Apps. Full Kubernetes control = AKS. Web app = App Service.

Lessons 123–124 · 16.2

Azure Container Instances (ACI)

Fastest way to run containers in Azure. Serverless — pay per second. No node/cluster management.

FeatureDetail
Startup timeSeconds
OS supportLinux and Windows containers
Public accessOptional public IP + DNS label
VNetVNet injection (private deployment)
StorageAzure Files mount for persistence
Restart policyAlways / OnFailure / Never
BillingPer vCPU/GB per second
# Deploy ACI from ACR image
az container create   --resource-group RG-Apps-GR   --name myapp-aci   --image septonaacr.azurecr.io/myapp:v1.0   --cpu 1 --memory 1.5   --dns-name-label septona-app-gr   --ports 80   --registry-login-server septonaacr.azurecr.io   --assign-identity  # use managed identity for ACR auth

# Check logs
az container logs --resource-group RG-Apps-GR --name myapp-aci

Lesson 125 · 16.3

Container Groups

Container Groups = multiple containers that share a lifecycle, network (same IP), and storage. Like a Kubernetes Pod.

  • All containers share the same public IP and can communicate via localhost
  • Can have multiple ports exposed
  • Sidecar pattern: main app + logging sidecar + proxy container
  • Deploy via ARM template or YAML file
# Deploy container group with YAML
az container create   --resource-group RG-Apps-GR   --file container-group.yaml

Lesson 126 · 16.4

Azure Container Apps

Managed serverless container platform built on Kubernetes. Handles orchestration transparently. Features KEDA-based autoscaling including scale-to-zero.

ACI

  • Simple, single containers
  • Manual scaling
  • No service discovery
  • Cheapest for burst

Container Apps

  • Microservices focus
  • KEDA autoscale (to zero)
  • Dapr integration
  • Ingress built-in

AKS

  • Full Kubernetes control
  • Any K8s workload
  • Complex networking
  • Most operational work

Lessons 127–129 · 16.5

Azure Container Registry (ACR)

Private Docker registry in Azure. Store, manage, and replicate container images.

SKUFeatures
BasicDev/test. 10GB storage. No geo-replication.
StandardProduction. 100GB. Webhooks.
PremiumGeo-replication, Private Link, token auth, 500GB.
# Create ACR
az acr create   --name septonaacr   --resource-group RG-DevOps-GR   --sku Basic

# Build image directly in ACR (no local Docker needed)
az acr build   --registry septonaacr   --image myapp:v1.0   .  # current directory with Dockerfile

# Push local image to ACR
az acr login --name septonaacr
docker tag myapp:latest septonaacr.azurecr.io/myapp:v1.0
docker push septonaacr.azurecr.io/myapp:v1.0

# Grant ACI/AKS access to ACR via managed identity
az role assignment create   --assignee MANAGED_IDENTITY_ID   --role AcrPull   --scope /subscriptions/.../registries/septonaacr

Chapter 09

Quiz

◈ Q01
Workload: batch job που τρέχει 10 λεπτά, μία φορά τη μέρα. Δεν χρειάζεται orchestration. Ποιο service;
  • A) AKS
  • B) Azure Container Instances (ACI)
  • C) App Service
  • D) Virtual Machine
✅ B — ACI. Short-lived, no orchestration needed, pay per second = ACI. AKS = complex orchestration. App Service = web hosting. VM = overkill for 10-minute batch.
◈ Q02
Πώς grants access στο ACI να pull images από private ACR χωρίς credentials στον κώδικα;
  • A) Username/password στο container create command
  • B) Managed Identity + AcrPull role assignment
  • C) ACR admin account enabled
  • D) Public ACR registry
✅ B — Managed Identity + AcrPull. Enable managed identity on ACI, assign AcrPull role to that identity on the ACR. No credentials needed. ACR admin account = not recommended (shared secret).
📌 Key Facts — Ch09
ACIServerless containers. Pay per second. No orchestration. Short-lived tasks.
Container AppsKEDA autoscale, Dapr, scale-to-zero. Between ACI and AKS.
AKSFull Kubernetes. Control plane is FREE. Pay for worker node VMs.
ACR + AcrPullGrant managed identity AcrPull role for secure no-credential image pull.

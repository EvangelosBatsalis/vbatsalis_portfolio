Creating a Virtual Machine

VM Series

SeriesΧαρακτηριστικάUse Case
B-series BurstableLow baseline CPU, burst creditsDev/test, web servers light load
D-seriesBalanced CPU/RAMGeneral purpose, ERP, web apps
E-seriesHigh memory ratioSAP HANA, in-memory databases

VM Size Naming

Size Format

Standard_D4s_v5
Standard = tier | D = General purpose | 4 = 4 vCPUs | s = premium storage | v5 = 5th gen

Key VM Creation Components

  • Region: Affects latency, compliance, pricing
  • Availability option: None, Availability Set, Availability Zone, VMSS
  • Image: Windows Server, Ubuntu, RHEL, or custom
  • Size: Series + vCPUs + RAM
  • Authentication: Password or SSH key (Linux)
  • Inbound ports: NSG rules (RDP 3389, SSH 22, HTTP 80)
  • OS Disk: Managed disk type
  • VNet/Subnet: Network placement
# Create VM με CLI
az vm create \
  --resource-group RG-Servers-GR \
  --name SRV-APP-GR-01 \
  --image Win2022Datacenter \
  --size Standard_D4s_v5 \
  --admin-username septonaadmin \
  --vnet-name VNet-Production-GR \
  --subnet Subnet-Servers \
  --zone 1 \
  --no-wait

# Custom Script Extension — run PS after deploy
az vm extension set \
  --resource-group RG-Servers-GR \
  --vm-name SRV-APP-GR-01 \
  --name CustomScriptExtension \
  --publisher Microsoft.Compute \
  --settings '{"commandToExecute":"powershell Install-WindowsFeature -Name Web-Server"}'

Azure VM Disk Options

Managed Disk Types

TypeMax IOPSLatencyUse Case
Ultra Disk160,000Sub-msSAP HANA, tier-1 DB
Premium SSD v280,000Sub-msProduction DB, ERP
Premium SSD Common20,000Single-digit msProduction workloads, OS disk
Standard SSD6,000Low-msWeb servers, dev/test
Standard HDD2,000High-msBackup, archival

Disk Roles

  • OS Disk: Every VM has one. Contains OS. Max 4 TiB.
  • Data Disk: Additional storage. Count depends on VM size. Max 32 TiB each.
  • Temporary Disk: NON-PERSISTENT — D: (Windows) or /dev/sdb (Linux). Lost on resize/redeploy/stop-deallocate. Only for pagefile/swap!
🎯
Temp disk data loss is expected behavior, NOT a bug. If exam asks "data in temp disk lost after resize" — that's correct. Never store important data on temp disk.

Lesson 81 · 11.3

VM Networking Options

  • NIC (Network Interface Card): VM can have multiple NICs (depends on size)
  • Public IP: Optional — for internet access. Static or Dynamic.
  • Private IP: Always assigned from subnet. Static or Dynamic (DHCP).
  • NSG: Can be associated with NIC or subnet
  • Accelerated Networking: Hardware-accelerated, lower latency (supported on certain sizes)
  • IP forwarding: Enable for network virtual appliances (NVA)
💡
Best Practice: Avoid public IPs on VMs. Use Azure Bastion for management access. If internet-facing, put behind Load Balancer or Application Gateway.

Critical Differences:
• Availability Set: Same datacenter, different Fault Domains (power/network) and Update Domains. Protects from hardware failure and planned maintenance.
• Availability Zone: Different physical buildings in same region. Protects from datacenter failure.
• Cannot combine Availability Set + Availability Zone for same VM.
• Cannot change availability option after VM creation — must recreate. 
# Create VM in Availability Zone 1
az vm create --zone 1 --name SRV-WEB-01 ...

# Create Availability Set
az vm availability-set create \
  --name AS-WebServers \
  --resource-group RG-Servers-GR \
  --platform-fault-domain-count 2 \
  --platform-update-domain-count 5

Resize VM & Additional Disks

Resize VM

  • Resize = αλλαγή VM size (more CPU/RAM)
  • Αν νέο size διαθέσιμο στο cluster → resize χωρίς downtime (live migration)
  • Αν ΔΕΝ διαθέσιμο → VM deallocates, moves to different cluster, restarts
  • Temp disk data ΧΑΝΕΤΑΙ κατά resize (always!)

Attach Data Disk

# Attach new managed data disk
az vm disk attach \
  --resource-group RG-Servers-GR \
  --vm-name SRV-APP-GR-01 \
  --name DataDisk-SQL-01 \
  --size-gb 512 \
  --sku Premium_LRS \
  --new

Lessons 88–90 · 11.7

VM Scale Sets (VMSS)

VM Scale Sets = deploy και manage identical VMs με auto-scaling. Ιδανικά για stateless workloads.

Uniform VMSS

  • Identical VMs, same image
  • Max 1000 instances
  • Simple autoscale
  • Stateless workloads

Flexible VMSS Recommended

  • Mix VM sizes possible
  • Availability Zone support
  • Better HA
  • Max 1000 instances

Autoscale Rules

  • Scale out (add VMs): when CPU > 80% for 10 minutes → add 2 VMs
  • Scale in (remove VMs): when CPU < 30% for 10 minutes → remove 1 VM
  • Cooldown period: Wait after scale event before next evaluation (default: 5 min)
  • Schedule-based scaling: Scale up Friday evening, scale down Monday morning
  • Min/Max instance count prevents runaway scaling

Disk Encryption: SSE vs ADE

SSE (Server-Side Encryption)ADE (Azure Disk Encryption)
What encryptsAzure infrastructure (automatic)OS-level (BitLocker/DM-Crypt)
WhenAt rest in Azure storageIn-use (while VM is running)
Default✅ Always on — cannot disable❌ Must explicitly enable
Key managementMMK or CMK (Key Vault)Key Vault required
OS visibilityTransparent to OSOS sees encrypted disk
Use caseStandard protection (everyone)Compliance requiring in-use encryption
🎯
SSE vs ADE for exam: SSE = automatic, always on, protects at rest in Azure. ADE = you enable it, uses BitLocker (Windows) or DM-Crypt (Linux), encrypts the disk at the OS level so even Azure cannot read the disk content. ADE requires Azure Key Vault for key management.
# Enable ADE on existing VM
az vm encryption enable \
  --resource-group RG-Servers-GR \
  --name SRV-APP-GR-01 \
  --disk-encryption-keyvault KeyVault-Septona-GR \
  --volume-type All

# Check encryption status
az vm encryption show \
  --resource-group RG-Servers-GR \
  --name SRV-APP-GR-01

Quiz — Virtual Machines

◈ Q01
VM data που ήταν στο temporary disk εξαφανίστηκε μετά από resize. Τι έγινε;
  • A) Bug — άνοιξε support ticket
  • B) Expected — temp disk είναι non-persistent
  • C) OS corruption — restore from backup
  • D) Storage account sync failure
✅ B — Expected behavior. Temporary disk (D: on Windows, /dev/sdb on Linux) is non-persistent by design. Data is lost on resize, redeploy, or stop-deallocate. Only use it for pagefile/temp files.
◈ Q02
Availability Set vs Availability Zone — ποιο SLA δίνει 99.99%;
  • A) Availability Set
  • B) Availability Zone
  • C) Και τα δύο
  • D) Single VM με Premium SSD
✅ B — Availability Zone. AZ = 99.99% SLA (different physical datacenters). AS = 99.95% (same datacenter, different FD/UD). Single VM Premium SSD = 99.9%.
◈ Q03
Ποια method επιτρέπει RDP access σε VM χωρίς public IP και χωρίς open port 3389;
  • A) VPN + NSG rule για port 3389
  • B) Azure Bastion
  • C) Public IP + firewall
  • D) Run Command extension
✅ B — Azure Bastion. Bastion provides browser-based RDP/SSH over HTTPS (443) without public IP on the VM or open RDP/SSH ports. Requires AzureBastionSubnet (/26 min) in the VNet.
◈ Q04
Compliance απαιτεί encryption of VM disks at the OS level (in-use). Ποιο feature;
  • A) SSE με MMK
  • B) SSE με CMK
  • C) Azure Disk Encryption (ADE)
  • D) Storage Account encryption
✅ C — ADE. Azure Disk Encryption uses BitLocker (Windows) or DM-Crypt (Linux) to encrypt at the OS level while the VM is running. SSE only encrypts data at rest in Azure storage — transparent to OS. ADE requires Key Vault.

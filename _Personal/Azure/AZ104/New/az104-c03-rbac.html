Role-Based Access Control

Το RBAC είναι το authorization system του Azure. Ελέγχει WHO μπορεί να κάνει WHAT σε WHICH resources. Βασίζεται στην αρχή Least Privilege — δίνεις μόνο ό,τι χρειάζεται. Κατανοήσε τα τρία βασικά στοιχεία: Security Principal + Role Definition + Scope.

Lesson 38 · 6.1

RBAC Overview

Το Azure RBAC (Role-Based Access Control) είναι το σύστημα authorization που ελέγχει την πρόσβαση σε Azure resources. Είναι ξεχωριστό από την Entra ID authentication — RBAC = τι κάνεις, Entra ID = ποιος είσαι.

👤
Security Principal
WHO gets access
User, Group, Service Principal, Managed Identity
📋
Role Definition
WHAT they can do
Set of allowed actions & data actions
🎯
Scope
WHERE they can do it
Management Group, Subscription, RG, Resource

Η Role Assignment = Security Principal + Role Definition + Scope. Αυτό είναι ένα record στο Azure RBAC system.

🎯
RBAC Key Rules:
• RBAC είναι additive — αν έχεις πολλά role assignments, οι permissions αθροίζονται
• Deny assignment wins over any Allow — Deny is explicit and takes priority
• Permissions κληρονομούνται από higher scopes (Subscription scope → ισχύει και σε RGs και resources)
• RBAC δεν ελέγχει τι κάνεις μέσα σε resource (π.χ. SQL queries) — μόνο τη διαχείριση του resource
👤

6.3

Role Definitions

Κάθε role είναι JSON με Actions (management operations) και DataActions (data plane operations):

# Structure ενός Role Definition
{
  "Name": "Custom Storage Reader",
  "Id": "guid",
  "IsCustom": true,
  "Description": "Can read storage but not write",
  "Actions": [
    "Microsoft.Storage/storageAccounts/read",
    "Microsoft.Storage/storageAccounts/blobServices/read"
  ],
  "NotActions": [],
  "DataActions": [
    "Microsoft.Storage/storageAccounts/blobServices/containers/blobs/read"
  ],
  "NotDataActions": [],
  "AssignableScopes": [
    "/subscriptions/your-subscription-id"
  ]
}
🎯
Actions vs DataActions: Actions = management plane (CRUD resources μέσω ARM). DataActions = data plane (read/write blobs, query SQL tables). Παράδειγμα: "Storage Blob Data Reader" DataAction = μπορείς να διαβάσεις blob content. Χωρίς DataAction, μπορείς να δεις το storage account αλλά όχι τα data.
🎯
6.4

Scopes & Inheritance

Management Group → κληρονομείται σε όλα τα subscriptions κάτω
Subscription → κληρονομείται σε όλα τα RGs
Resource Group → κληρονομείται σε όλα τα resources
Resource → μόνο αυτό το resource

Αν κάποιος έχει Contributor σε Subscription scope → έχει Contributor σε ΟΛΑ τα Resource Groups και resources.

🎯
ReadOnly Lock + listKeys: Αν βάλεις ReadOnly lock σε storage account, ακόμα και Owners δεν μπορούν να κάνουν listKeys (είναι POST operation). Αυτό μπλοκάρει access σε storage data μέσω keys. Πολύ συχνή exam trap.

💡
Entra ID Roles vs RBAC Roles: Δύο ξεχωριστά role systems! Entra ID roles (Global Admin, User Admin) ελέγχουν Entra ID objects. Azure RBAC roles ελέγχουν Azure resources. Global Admin δεν έχει αυτόματα πρόσβαση σε Azure VMs — χρειάζεται RBAC assignment.
# Assign Contributor role σε user για specific RG
az role assignment create \
  --assignee "developer@septona.gr" \
  --role "Contributor" \
  --resource-group "RG-Dev-GR"

# Assign Reader σε group για subscription
az role assignment create \
  --assignee "GROUP-OBJECT-ID" \
  --role "Reader" \
  --scope "/subscriptions/SUBSCRIPTION-ID"

# List role assignments σε RG
az role assignment list \
  --resource-group "RG-Dev-GR" \
  --output table

# PowerShell — list assignments
Get-AzRoleAssignment -ResourceGroupName "RG-Dev-GR" | 
  Select-Object DisplayName, RoleDefinitionName, Scope

Lesson 43 · 6.6

Custom RBAC Roles

Όταν τα built-in roles δεν καλύπτουν ακριβώς αυτό που θέλεις, δημιουργείς custom role. Μέχρι 5000 custom roles ανά tenant.

Realistic ScenarioCustom Role — Septona VM Operator

Κατάσταση: Το operations team πρέπει να μπορεί να start/stop/restart VMs αλλά ΌΧΙ να τα δημιουργεί ή διαγράφει. Κανένα built-in role δεν ταιριάζει ακριβώς.

# custom-vm-operator.json
{
  "Name": "Septona VM Operator",
  "Description": "Start, stop, restart VMs only",
  "Actions": [
    "Microsoft.Compute/virtualMachines/start/action",
    "Microsoft.Compute/virtualMachines/powerOff/action",
    "Microsoft.Compute/virtualMachines/restart/action",
    "Microsoft.Compute/virtualMachines/read",
    "Microsoft.Compute/virtualMachines/instanceView/read"
  ],
  "NotActions": [],
  "AssignableScopes": ["/subscriptions/SUBSCRIPTION-ID"]
}

# Create custom role
az role definition create --role-definition custom-vm-operator.json

# Assign σε operations team group
az role assignment create \
  --assignee "GRP-OPERATIONS-OBJECT-ID" \
  --role "Septona VM Operator" \
  --scope "/subscriptions/SUBSCRIPTION-ID"

6.7

Managed Identity

Το Managed Identity επιτρέπει σε Azure resources (VM, App Service, Function) να authenticate σε άλλες Azure services χωρίς credentials (passwords, keys) στον κώδικα.

System-assigned

  • Tied στο lifetime του resource
  • Διαγράφεται μαζί με το resource
  • 1:1 resource-to-identity
  • Enable μέσω resource settings
  • Απλό configuration

User-assigned

  • Standalone resource
  • Μπορεί να χρησιμοποιηθεί σε πολλά resources
  • Independent lifecycle
  • Δημιουργείς ξεχωριστά
  • Πιο flexible για multi-resource
# Enable system-assigned managed identity σε VM
az vm identity assign \
  --resource-group "RG-Servers-GR" \
  --name "SRV-APP-GR-01"

# Assign role στο managed identity (π.χ. read storage)
IDENTITY_ID=$(az vm show \
  -g RG-Servers-GR -n SRV-APP-GR-01 \
  --query "identity.principalId" -o tsv)

az role assignment create \
  --assignee $IDENTITY_ID \
  --role "Storage Blob Data Reader" \
  --scope "/subscriptions/.../storageAccounts/septonabackup"

# Τώρα το VM μπορεί να access storage χωρίς storage keys!
# Στον κώδικα χρησιμοποιείς DefaultAzureCredential()

Lesson 45 · 6.8

Interpret Access Assignments

Το Check Access feature στο portal σου δείχνει τι access έχει ένας user — χρήσιμο για troubleshooting.

  • Portal: Resource → Access Control (IAM) → Check Access → επιλέγεις user/group
  • Βλέπεις: ποια roles έχει, από ποιο scope, inherited ή direct
  • PowerShell: Get-AzRoleAssignment -SignInName "user@septona.gr"
Realistic ScenarioAccess Troubleshooting — "Why can't I delete this VM?"

Κατάσταση: Developer λέει "μπορώ να δω τα VMs αλλά δεν μπορώ να τα διαγράψω". Τι ελέγχεις;

  1. Portal → RG-Dev-GR → Access Control (IAM) → Check Access → developer@septona.gr
  2. Βλέπεις: Reader role σε Subscription (inherited) + Virtual Machine Contributor σε RG
  3. VM Contributor = μπορεί να manage VMs αλλά όχι να τα διαγράψει από RG? Ναι, μπορεί delete VM αλλά...
    Ελέγχεις: υπάρχει Delete Lock στο RG;
  4. Portal → RG-Dev-GR → Locks → βρίσκεις CanNotDelete lock
  5. Λύση: Remove lock (αν επιτρέπεται) ή εξήγησε ότι lock υπάρχει για λόγο

Chapter 03

Quiz — RBAC

◈ Q01
User έχει Reader role σε Subscription και Contributor role σε Resource Group RG-Dev. Τι μπορεί να κάνει σε ένα VM μέσα στο RG-Dev;
  • A) Μόνο read — Reader από subscription wins
  • B) Full Contributor permissions — RBAC είναι additive
  • C) Τίποτα — conflicting roles cancel each other
  • D) Εξαρτάται από το role που assigned πρώτο
✅ B — RBAC είναι additive. Contributor σε RG scope includes VM actions. Reader από subscription δεν αφαιρεί Contributor permissions. Additive = highest permission wins. Αν θέλεις restriction, χρειάζεσαι Deny assignment.
◈ Q02
Θέλεις application που τρέχει σε Azure VM να κάνει read/write σε Azure Key Vault secrets χωρίς να αποθηκεύσεις credentials στον κώδικα. Ποια λύση;
  • A) Δημιουργείς service principal, βάζεις secret σε app config
  • B) Χρησιμοποιείς τον admin account
  • C) System-assigned Managed Identity + Key Vault Secrets Officer role
  • D) Storage access keys
✅ C — Managed Identity. System-assigned managed identity δημιουργεί αυτόματα identity για το VM. Assign Key Vault Secrets Officer role σε αυτό το identity. Ο κώδικας χρησιμοποιεί DefaultAzureCredential() — no credentials stored.
◈ Q03
User έχει Owner role σε Resource Group αλλά δεν μπορεί να κάνει listKeys σε storage account μέσα στο RG. Ποια η αιτία;
  • A) Χρειάζεται Storage Blob Data Owner role
  • B) Υπάρχει ReadOnly Lock στο storage account ή RG
  • C) Storage keys disabled
  • D) Χρειάζεται Entra ID Global Admin
✅ B — ReadOnly Lock. ReadOnly lock μπλοκάρει POST operations. listKeys() είναι POST. Ακόμα και Owner δεν μπορεί να πάρει access keys αν υπάρχει ReadOnly lock. Πρέπει πρώτα να αφαιρεθεί το lock (αν έχεις permissions).
◈ Q04
Θέλεις να δώσεις σε developer access να manage μόνο VMs (start/stop/resize) χωρίς access σε networking ή storage. Ποιο role;
  • A) Contributor
  • B) Owner
  • C) Virtual Machine Contributor
  • D) Reader
✅ C — Virtual Machine Contributor. Built-in role που δίνει access μόνο σε VM management — δεν περιλαμβάνει networking, storage, ή role assignments. Contributor = full resource management (includes VNet, storage κλπ) — πολύ broad.

Key Facts — Chapter 03

📌 Flashcard Summary
RBAC = additiveMultiple roles add up. Deny explicitly overrides all.
Owner vs ContributorOwner = Contributor + manage access. Only Owner can assign roles.
ReadOnly Lock + listKeysReadOnly blocks POST → cannot list storage keys
Managed IdentityNo credentials needed. System-assigned (1:1) or User-assigned (reusable)
Actions vs DataActionsActions = manage resource. DataActions = access data inside resource.
Entra Roles vs RBACDifferent systems. Entra = directory objects. RBAC = Azure resources.

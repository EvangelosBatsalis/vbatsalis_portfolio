Lessons 63–66 · 8.4

Networking, Encryption & Data Protection

Firewall & Network Access

  • All networks (default): Public internet access
  • Selected networks: Specific IP ranges or VNets via Service Endpoints
  • Private Endpoint: Storage gets private IP in VNet — no public exposure
  • Trusted services: Allows Azure Backup, Monitor even when firewall on

Data Protection Features

  • Soft delete (Blobs): Retain deleted blobs 1–365 days. Default: 7 days.
  • Soft delete (Containers): Same for containers
  • Blob versioning: Auto-saves all versions on write/delete
  • Point-in-time restore: Restore blocks to any past point (needs versioning)
  • Immutability policies: WORM (Write Once Read Many) — locked blobs

Encryption

  • At rest: Automatic 256-bit AES — cannot disable
  • MMK: Microsoft manages keys (default)
  • CMK: Customer manages keys in Azure Key Vault
  • In transit: HTTPS enforced with min TLS 1.2

Revoke SAS: To instantly revoke a SAS: if it uses a Stored Access Policy → delete/modify the policy. If signed with account key → rotate the key (affects ALL SAS signed with that key). User Delegation SAS → revoke the Entra ID permissions.
# Generate SAS token for blob (read, 48h)
az storage blob generate-sas \
  --account-name septonabackupgr \
  --container-name backups \
  --name vm-backup-2026.vhd \
  --permissions r \
  --expiry 2026-04-03 \
  --https-only

Entra ID (RBAC) Access Control

Αντί για Access Keys, χρησιμοποίησε RBAC roles για granular, identity-based access:

RoleAccess
Storage Blob Data OwnerFull access to blob data + ACLs
Storage Blob Data ContributorRead/write/delete blobs
Storage Blob Data ReaderRead blobs only
Storage File Data Privileged ContributorRead/write Azure Files
Storage Queue Data ContributorRead/write queues
💡
Μεγάλη διαφορά: "Storage Account Contributor" (RBAC) = manages the storage account resource αλλά ΔΕΝ δίνει access στα DATA. "Storage Blob Data Reader" (RBAC) = reads blob data. Χρειάζεσαι data-plane role για πρόσβαση σε blobs.

Lesson 73 · 9.1

Lifecycle Management

Αυτόματη μετακίνηση blobs μεταξύ tiers και διαγραφή βάσει rules. Εκτελείται μία φορά ημερησίως.

# Lifecycle policy — Cool after 30d, Archive after 365d, Delete after 2555d
{
  "rules": [{
    "name": "MarketingAssets",
    "type": "Lifecycle",
    "definition": {
      "filters": {
        "blobTypes": ["blockBlob"],
        "prefixMatch": ["marketing/"]
      },
      "actions": {
        "baseBlob": {
          "tierToCool": {"daysAfterModificationGreaterThan": 30},
          "tierToArchive": {"daysAfterModificationGreaterThan": 365},
          "delete": {"daysAfterModificationGreaterThan": 2555}
        }
      }
    }
  }]
}
Realistic ScenarioCosmoprof Assets — Tiered Storage

Κατάσταση: Εκατοντάδες GB φωτογραφίες/videos από εκθέσεις. Πρόσφατα 30 ημερών = γρήγορη πρόσβαση. Παλαιότερα σπάνια χρειάζονται.

  1. Νέα αρχεία ανεβαίνουν στο Hot tier
  2. Lifecycle policy: μετά 30 ημέρες → Cool
  3. Μετά 365 ημέρες → Archive
  4. Soft Delete enabled 30 ημέρες — προστασία από τυχαία διαγραφή

Αποτέλεσμα: αυτόματη cost optimization χωρίς manual work.

Lesson 75 · 9.2

AzCopy & Storage Tools

AzCopy

High-performance CLI tool για data transfer. Supports resume, server-side copy.

# Login
azcopy login

# Upload directory
azcopy copy 'C:\Backups\' \
  'https://septonabackup.blob.core.windows.net/backups/' \
  --recursive

# Sync (incremental — only changed files)
azcopy sync \
  'C:\FileServer\' \
  'https://septonafiles.blob.core.windows.net/shared?SAS' \
  --recursive --delete-destination true

# Server-side copy between accounts
azcopy copy \
  'https://source.blob.core.windows.net/c?SAS' \
  'https://dest.blob.core.windows.net/c?SAS' \
  --recursive

Other Tools

  • Azure Storage Explorer: GUI app (Windows/Mac/Linux) — browse, upload, download, manage SAS
  • Storage Browser (Portal): Web-based storage management in Azure portal
  • Azure Import/Export: Physical drives sent to datacenter for massive transfers
  • Azure Data Box: Appliance sent by Microsoft — 35TB (Disk), 80TB (Box), 800TB (Heavy)

Azure Files

Azure Files = fully managed SMB/NFS file shares. Mount as network drive (Z:\) from Windows, Linux, macOS. Replaces on-premises file servers.

Azure FilesBlob Storage
ProtocolSMB (port 445), NFSHTTP/HTTPS REST
Access modelMount as drive letterURL-based SDK
Shared access✅ Multiple users/appsObject-based
Use caseFile server replacementUnstructured data, backups
⚠️
Port 445 Problem: SMB uses port 445. Many ISPs/corporate firewalls block outbound 445. Fix: use Azure VPN, ExpressRoute, or Azure File Sync (bypasses 445 requirement).

Azure File Sync

Syncs on-premises Windows file servers with Azure Files. Enables cloud tiering — cold files move to cloud, freeing local disk.

# Mount Azure File Share on Windows
net use Z: \\septonafiles.file.core.windows.net\shared /user:AZURE\septonafiles ACCESS_KEY

# Create file share
az storage share create \
  --name company-shared \
  --account-name septonafiles \
  --quota 100
Realistic ScenarioFile Server Migration — Septona GR

Κατάσταση: On-prem file server (2TB data) πρέπει να μεταφερθεί στο cloud. Users πρέπει να εξακολουθούν να βλέπουν Z:\ drive.

  1. Δημιουργία Azure File Share: septona-shared
  2. Deploy Azure File Sync agent στον on-prem server
  3. Register server, create Sync Group
  4. Server Endpoint: D:\CompanyShare, Cloud Tiering: ON (80% free space)
  5. Initial sync: 2TB upload στο Azure
  6. Users continue using Z:\ — cold files served from cloud on-demand

Quiz — Storage

◈ Q01
Archive tier blob χρειάζεται σε λιγότερο από 1 ώρα. Τι επιλέγεις;
  • A) Standard priority rehydration — 15 ώρες
  • B) High priority rehydration — 1 ώρα
  • C) Copy με AzCopy — instant
  • D) Archive blobs είναι πάντα accessible σε seconds
✅ B — High priority rehydration. Archive blobs are OFFLINE. Must rehydrate (change tier). High priority = up to 1 hour but costs more. Standard = up to 15 hours. AzCopy cannot read offline blobs.
◈ Q02
Θέλεις max protection + read access σε secondary region πάντα. Ποιο redundancy;
  • A) GRS
  • B) GZRS
  • C) RA-GRS
  • D) RA-GZRS
✅ D — RA-GZRS. Zone redundant primary (ZRS) + geo secondary (GRS) + read access (RA) = maximum protection with always-available secondary reads. RA-GRS has LRS primary (not zone redundant).
◈ Q03
SAS token δόθηκε σε εξωτερικό συνεργάτη και θέλεις να το revoke-άρεις αμέσως χωρίς να επηρεαστούν άλλα SAS. Πώς;
  • A) Rotate account keys
  • B) Delete/modify the Stored Access Policy που reference-άρει το SAS
  • C) Περίμενε να expire
  • D) Disable storage account
✅ B — Stored Access Policy. If SAS references a policy, deleting/modifying the policy instantly invalidates those SAS tokens. Rotating account key invalidates ALL SAS signed with that key — affects everyone.
◈ Q04
Tags που βάλεις στο Resource Group μεταφέρονται αυτόματα στα Storage Accounts μέσα;
  • A) Ναι, tags κληρονομούνται πάντα
  • B) Ναι, αλλά μόνο αν το storage account δεν έχει δικά του tags
  • C) Όχι, tags δεν κληρονομούνται στο Azure
  • D) Ναι, αλλά μόνο σε Standard GPv2 accounts
✅ C — Tags ΔΕΝ κληρονομούνται. Azure tags never inherit from RG to resources. Use Azure Policy with Append or Modify effect to auto-apply tags to resources in a RG.

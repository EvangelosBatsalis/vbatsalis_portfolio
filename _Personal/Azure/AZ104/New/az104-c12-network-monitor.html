22.2

Key Diagnostic Tools

IP Flow Verify

Tests a specific traffic flow against NSG rules. Input: source IP, destination IP, port, protocol, direction. Output: Allow or Deny + which NSG rule caused it.

# Test if RDP is allowed from my IP to VM
az network watcher test-ip-flow   --resource-group RG-Servers-GR   --vm SRV-APP-GR-01   --direction Inbound   --protocol TCP   --local 10.10.1.4:3389   --remote 1.2.3.4:5000

Next Hop

Shows the next hop type and IP for traffic leaving a VM's NIC. Types: Internet, VirtualAppliance, VirtualNetworkGateway, VnetLocal, None (no route).

# Check routing from VM to external IP
az network watcher show-next-hop   --resource-group RG-Servers-GR   --vm SRV-APP-GR-01   --source-ip 10.10.1.4   --dest-ip 8.8.8.8

Packet Capture

# Start packet capture (stores to storage account)
az network watcher packet-capture create   --resource-group RG-Servers-GR   --vm SRV-APP-GR-01   --name CaptureHTTPS   --storage-account septonadiag   --filters '[{"protocol":"TCP","remotePort":"443"}]'
🎯
IP Flow Verify vs Next Hop:
IP Flow Verify = Is traffic ALLOWED by NSG? (firewall perspective)
Next Hop = WHERE does traffic GO? (routing perspective)
Both together = complete network troubleshooting picture.

22.3

NSG Flow Logs

NSG Flow Logs record information about all traffic flowing through NSGs — stored in Storage Account as JSON.

  • Enabled per NSG
  • Records: timestamp, source/dest IP, port, protocol, allow/deny, bytes
  • Version 2: also includes bytes and packet count
  • Stored in Storage Account — path: insights-logs-networksecuritygroupflowevent
  • Can be analyzed in: Traffic Analytics (via Log Analytics), Splunk, Grafana
# Enable NSG Flow Logs
az network watcher flow-log create   --resource-group RG-Network-GR   --name FlowLog-NSG-Servers   --nsg NSG-Servers-GR   --storage-account septonadiag   --enabled true   --retention 30   --format JSON   --log-version 2
Realistic ScenarioNetwork Troubleshooting — VM Can't Reach SQL Server

Problem: App VM (10.10.1.10) can't connect to SQL Server (10.10.2.20) on port 1433.

  1. IP Flow Verify: Source=10.10.1.10, Dest=10.10.2.20, Port=1433, Protocol=TCP → Result: DENY, Rule: DenyAll (NSG-Database)
  2. NSG-Database doesn't have rule for port 1433 from app subnet
  3. Add rule: Allow TCP 1433 from 10.10.1.0/24 to SQL servers
  4. Verify with IP Flow Verify again → Allow
  5. Enable NSG Flow Logs to monitor ongoing traffic

Quiz

◈ Q01
Θέλεις να δεις αν NSG rules μπλοκάρουν traffic από VM-A στο VM-B port 3389. Ποιο tool;
  • A) Next Hop
  • B) IP Flow Verify
  • C) Packet Capture
  • D) Connection Monitor
✅ B — IP Flow Verify. Tests specific traffic flow against NSG rules. Output: Allow or Deny + which rule. Next Hop = routing path. Packet Capture = capture raw traffic. Connection Monitor = continuous testing.
◈ Q02
NSG Flow Logs αποθηκεύονται σε;
  • A) Log Analytics Workspace
  • B) Azure Storage Account
  • C) Azure Monitor Metrics
  • D) Event Hub
✅ B — Storage Account. NSG Flow Logs are stored as JSON in a Storage Account. From there they can be analyzed using Traffic Analytics (which uses Log Analytics) or third-party tools.

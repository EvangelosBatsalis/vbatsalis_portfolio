Lesson 94 · 12.1

What is an ARM Template?

An Azure Resource Manager (ARM) Template is a JSON file that declaratively defines the infrastructure and configuration for Azure resources. You describe WHAT you want, ARM figures out HOW to deploy it.

Benefits

  • Declarative: Describe desired state — no need to write deployment scripts
  • Idempotent: Deploy same template multiple times = same result
  • Repeatable: Dev → Test → Prod with same template, different parameters
  • Modular: Linked templates, template specs
  • Validation: Pre-flight validation before actual deployment
💡
IaC Comparison: ARM Templates = Azure-native JSON. Bicep = Azure-native DSL (simpler syntax). Terraform = multi-cloud HCL. For AZ-104 exam: focus on ARM Templates and Bicep basics.

Lesson 95 · 12.2

ARM Template Structure

{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {
    "vmName": {
      "type": "string",
      "defaultValue": "SRV-APP-GR-01",
      "minLength": 1,
      "maxLength": 15,
      "metadata": { "description": "Name of the virtual machine" }
    },
    "adminPassword": {
      "type": "securestring"  // Never exposed in output/logs
    }
  },
  "variables": {
    "nicName": "[concat(parameters('vmName'), '-nic')]"
  },
  "resources": [
    {
      "type": "Microsoft.Compute/virtualMachines",
      "apiVersion": "2023-03-01",
      "name": "[parameters('vmName')]",
      "location": "[resourceGroup().location]",
      "properties": { /* VM config */ }
    }
  ],
  "outputs": {
    "vmId": {
      "type": "string",
      "value": "[resourceId('Microsoft.Compute/virtualMachines', parameters('vmName'))]"
    }
  }
}

Sections Explained

SectionRequiredPurpose
$schema✅Validates template version
contentVersion✅Version tracking
parameters❌Input values — allow customization per deployment
variables❌Computed values reused across template
resources✅Azure resources to deploy
outputs❌Return values after deployment

Lessons 97–98 · 12.3

Deploy ARM Templates

# Deploy via Azure CLI
az deployment group create   --resource-group RG-Servers-GR   --template-file vm-template.json   --parameters vmName=SRV-NEW-01 adminPassword=P@ssw0rd!

# Deploy via PowerShell
New-AzResourceGroupDeployment   -ResourceGroupName "RG-Servers-GR"   -TemplateFile "vm-template.json"   -vmName "SRV-NEW-01"

# What-if (preview changes before deploy)
az deployment group what-if   --resource-group RG-Servers-GR   --template-file vm-template.json

# Validate template (syntax check)
az deployment group validate   --resource-group RG-Servers-GR   --template-file vm-template.json
🎯
What-if vs Validate: Validate = check template syntax and resource types are valid. What-if = shows EXACT changes that will be made (add/delete/modify resources) without deploying. Both are dry-runs but what-if is more powerful.

Lesson 97 · 12.4

Template Specs

Template Specs = store ARM templates as Azure resources. Version them, share across organization, control access with RBAC.

# Create Template Spec
az ts create   --name VmTemplate   --resource-group RG-Templates   --location westeurope   --version "1.0"   --template-file vm-template.json

# Deploy from Template Spec
az deployment group create   --resource-group RG-Servers-GR   --template-spec "/subscriptions/.../resourceGroups/RG-Templates/providers/Microsoft.Resources/templateSpecs/VmTemplate/versions/1.0"

Lesson 100 · 12.5

Custom Script Extensions

Custom Script Extension runs a script (PowerShell/bash) on a VM after deployment — used for post-provisioning configuration.

# In ARM template — install IIS after VM deployment
{
  "type": "Microsoft.Compute/virtualMachines/extensions",
  "name": "[concat(parameters('vmName'),'/InstallIIS')]",
  "apiVersion": "2023-03-01",
  "properties": {
    "publisher": "Microsoft.Compute",
    "type": "CustomScriptExtension",
    "settings": {
      "commandToExecute": "powershell Install-WindowsFeature -Name Web-Server -IncludeManagementTools"
    }
  }
}
🎯
Custom Script Extension runs ONCE after deploy. If you need ongoing configuration management, use DSC (Desired State Configuration) extension instead. CSE = one-shot. DSC = continuous compliance.

Azure Bicep

Azure Bicep is a Domain Specific Language (DSL) for Azure infrastructure. Compiles to ARM Templates — same capabilities but cleaner syntax.

Bicep vs ARM JSON

ARM JSONBicep
SyntaxVerbose JSONClean DSL
Compile toItself (JSON)ARM Template (JSON)
ModulesLinked templates (complex)Native module support
Type safetyLimitedFull type checking
VS Code supportBasicExcellent (IntelliSense)

Bicep Example — Same VM as ARM above

// vm.bicep — equivalent to the ARM JSON above
param vmName string = 'SRV-APP-GR-01'
param adminPassword securestring
param location string = resourceGroup().location

var nicName = '${vmName}-nic'

resource nic 'Microsoft.Network/networkInterfaces@2023-04-01' = {
  name: nicName
  location: location
  properties: { // NIC config }
}

resource vm 'Microsoft.Compute/virtualMachines@2023-03-01' = {
  name: vmName
  location: location
  properties: {
    hardwareProfile: { vmSize: 'Standard_D4s_v5' }
    osProfile: {
      computerName: vmName
      adminUsername: 'septonaadmin'
      adminPassword: adminPassword
    }
  }
}

output vmId string = vm.id

Bicep Commands

# Install Bicep CLI
az bicep install

# Build Bicep → ARM JSON
az bicep build --file vm.bicep

# Decompile existing ARM JSON → Bicep
az bicep decompile --file vm-template.json

# Deploy Bicep directly (auto-compiles)
az deployment group create   --resource-group RG-Servers-GR   --template-file vm.bicep   --parameters adminPassword=P@ssw0rd!

Quiz — ARM & Bicep

◈ Q01
Θέλεις να δεις ποια resources θα αλλάξουν ΠΡΙΝ deploy ARM template. Ποια command;
  • A) az deployment group validate
  • B) az deployment group what-if
  • C) az deployment group create --dry-run
  • D) az template preview
✅ B — what-if. Shows exact changes (add/modify/delete) that would happen. Validate = syntax check only. --dry-run doesn't exist in ARM CLI. what-if is the correct preview command.
◈ Q02
Ποιος τύπος parameter πρέπει να χρησιμοποιείται για passwords σε ARM templates;
  • A) string
  • B) securestring
  • C) password
  • D) encrypted
✅ B — securestring. securestring values are never logged, never shown in deployment history, and never exposed in Azure Monitor. Use securestring for any sensitive value (passwords, connection strings, API keys).

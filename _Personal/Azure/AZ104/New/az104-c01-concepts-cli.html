Azure Resource Hierarchy

Κατανόησε την ιεραρχία — σημαντική για RBAC, Policy και Locks:

Hierarchy — Top to Bottom

Tenant (Entra ID) — Root organization, one per company
  └── Management Group — Logical grouping of subscriptions (max 6 levels deep)
      └── Subscription — Billing unit, trust relationship with Entra ID
          └── Resource Group — Logical container for resources (same lifecycle)
              └── Resource — Actual Azure service (VM, Storage Account, VNet, κλπ)

🎯
Exam: RBAC & Policy inheritance: Ό,τι ορίζεις σε υψηλότερο scope κληρονομείται προς τα κάτω. RBAC assignment σε Subscription = ισχύει για όλα τα RGs και resources. Policy σε Management Group = ισχύει για όλες τις subscriptions κάτω από αυτό. Locks δεν κληρονομούνται αυτόματα — πρέπει να τα ορίσεις ξεχωριστά.

Overview of Azure VM and App Services

Δύο fundamentally διαφορετικά compute models — η επιλογή μεταξύ τους είναι πολύ συχνή ερώτηση στο AZ-104.

IaaS vs PaaS vs SaaS — Το Μοντέλο

ModelΕσύ διαχειρίζεσαιAzure διαχειρίζεταιΠαράδειγμα
On-PremisesΤα πάντα (hardware, OS, runtime, app, data)ΤίποταSeptona on-prem server
IaaS
Infrastructure as a Service		OS, runtime, middleware, app, dataHardware, hypervisor, network, storageAzure VM, Managed Disks
PaaS
Platform as a Service		App, data (και μερικές settings)OS patches, runtime, scaling, hardwareApp Service, Azure SQL, ACI
SaaS

Azure Virtual Machines — Quick Overview

Βαθύτερη κάλυψη στο Chapter 06. Εδώ: το conceptual framework.

  • IaaS model — full OS control, εσύ κάνεις patching και security
  • Επιλέγεις: Series (B/D/E/F/N), Size (cores, RAM, disk IOPS), OS, Region, Availability
  • Χρησιμοποιείς για: legacy apps, custom OS configuration, full control requirements
  • Billing: per second (Linux) ή per minute (Windows) όταν running. Stop/deallocate = no compute cost.

Azure App Service — Quick Overview

Βαθύτερη κάλυψη στο Chapter 08. Εδώ: το conceptual framework.

  • PaaS model — δεν διαχειρίζεσαι OS ή patching
  • Υποστηρίζει: .NET, Node.js, Python, PHP, Java, Ruby, Docker containers
  • Built-in: auto-scaling, load balancing, deployment slots, SSL certificates
  • Χρησιμοποιείς για: web apps, REST APIs, mobile backends
Realistic ScenarioSeptona — VM vs App Service Decision

Κατάσταση: Το IT team πρέπει να αποφασίσει πού να τρέξει τρεις εφαρμογές:

1. ERP System (Microsoft Dynamics NAV legacy): Απαιτεί Windows Server 2019, specific registry settings, custom DLLs. → Azure VM (IaaS) — χρειάζεσαι full OS control.

2. Corporate web portal (.NET 8): Standard web app, automatic scaling needed, δεν χρειάζεσαι OS access. → App Service (PaaS) — zero OS management, built-in scaling.

3. Data processing scripts (Python): Τρέχουν κατά διαστήματα, 5–10 λεπτά ανά run. → Azure Functions ή Container Instances — pay per execution, no idle cost.

Scripting on the AZ-104 Exam

Πολλοί φοβούνται τις scripting ερωτήσεις. Η πραγματικότητα: δεν χρειάζεσαι να γράψεις κώδικα από μνήμης. Το exam σε ρωτά να αναγνωρίσεις τη σωστή εντολή ή να συμπληρώσεις κενά (completion type questions).

Τι Ρωτά Το Exam

  • Αναγνώριση σωστής εντολής: "Ποια εντολή δημιουργεί VM;" → az vm create ή New-AzVM
  • Συμπλήρωση παραμέτρου: "Ποιο parameter ορίζει το resource group;" → --resource-group ή -ResourceGroupName
  • Σωστή σύνταξη: PowerShell vs CLI διαφορές (verb-noun vs az subcommand)
  • Output handling: -o json, | ConvertTo-Json, query με --query

PowerShell vs Azure CLI — Key Differences

Syntax patternVerb-AzNoun (PascalCase)az group subcommand (lowercase)
LanguagePowerShell (cross-platform)Python-based CLI (cross-platform)
PlatformWindows, Linux, macOS, Cloud ShellWindows, Linux, macOS, Cloud Shell
OutputObjects (pipe to other cmdlets)JSON, table, tsv (--output flag)

🎯
Exam Strategy: Αν δεις ερώτηση με PowerShell κώδικα — ψάξε για -ResourceGroupName, -Name, -Location patterns. Αν δεις CLI — ψάξε για --resource-group, --name, --location. Το Az prefix στο PowerShell ξεχωρίζει τις Azure εντολές από τις native PS εντολές.

Lessons 16–18 · Section 3.2

PowerShell Az Module

Το Az module είναι το επίσημο PowerShell module για Azure (αντικατέστησε το παλαιό AzureRM). Τρέχει σε Windows, Linux, macOS και Azure Cloud Shell.

Installation & Setup

# Install Az module (PowerShell 7+ recommended)
Install-Module -Name Az -Scope CurrentUser -Repository PSGallery -Force

# Update existing installation
Update-Module -Name Az

# Verify installation
Get-Module -Name Az -ListAvailable

# Check PowerShell version (needs 5.1+ or PowerShell 7+)
$PSVersionTable.PSVersion

Authentication

# Interactive login — opens browser
Connect-AzAccount

# Login με specific tenant (πολλαπλοί tenants)
Connect-AzAccount -Tenant "your-tenant-id"

# Service Principal login (automation, CI/CD)
$cred = New-Object System.Management.Automation.PSCredential("app-id", ("secret" | ConvertTo-SecureString -AsPlainText -Force))
Connect-AzAccount -ServicePrincipal -Credential $cred -Tenant "tenant-id"

# Verify current connection
Get-AzContext

Essential Az Commands — AZ-104 Exam Vocabulary

Verb PatternExample CommandsPurpose
Get-Az*Get-AzVM, Get-AzResourceGroup, Get-AzSubscriptionList / retrieve resources
New-Az*New-AzVM, New-AzResourceGroup, New-AzVirtualNetworkCreate new resources
Set-Az*Set-AzVM, Set-AzStorageAccountModify existing resources
Remove-Az*Remove-AzVM, Remove-AzResourceGroupDelete resources
Start-Az*Start-AzVM, Start-AzWebAppStart resources
Stop-Az*Stop-AzVM, Stop-AzWebAppStop resources
Update-Az*Update-AzVM, Update-AzFunctionAppUpdate/patch resources

Working with Resources — Common Patterns

# ─── RESOURCE GROUPS ───────────────────────────────────────────
# Δημιουργία Resource Group
New-AzResourceGroup -Name "RG-Servers-GR" -Location "westeurope"

# List όλα τα resource groups
Get-AzResourceGroup

# ─── VIRTUAL MACHINES ──────────────────────────────────────────
# List όλα τα VMs στο subscription
Get-AzVM

# List VMs σε specific RG
Get-AzVM -ResourceGroupName "RG-Servers-GR"

# Start / Stop VM
Start-AzVM -ResourceGroupName "RG-Servers-GR" -Name "SRV-APP-GR-01"
Stop-AzVM  -ResourceGroupName "RG-Servers-GR" -Name "SRV-APP-GR-01" -Force

# ─── STORAGE ───────────────────────────────────────────────────
# Δημιουργία Storage Account
New-AzStorageAccount `
  -ResourceGroupName "RG-Storage-GR" `
  -Name "septonabackupgr" `
  -Location "westeurope" `
  -SkuName "Standard_GRS" `
  -Kind "StorageV2"

# ─── TAGGING ───────────────────────────────────────────────────
# Add tags σε resource group
Set-AzResourceGroup -Name "RG-Servers-GR" `
  -Tag @{Environment="Production"; CostCenter="IT-GR"; Owner="vag@septona.gr"}

# ─── ROLE ASSIGNMENTS ──────────────────────────────────────────
# Assign Contributor role σε user για specific RG
New-AzRoleAssignment `
  -ObjectId "user-object-id" `
  -RoleDefinitionName "Contributor" `
  -ResourceGroupName "RG-Servers-GR"

Piping & Filtering (PowerShell superpower)

# Get VMs και filter όσα είναι stopped
Get-AzVM -Status | Where-Object { $_.PowerState -eq "VM deallocated" }

# Start όλα τα stopped VMs σε ένα RG
Get-AzVM -ResourceGroupName "RG-Servers-GR" -Status |
  Where-Object { $_.PowerState -ne "VM running" } |
  ForEach-Object { Start-AzVM -ResourceGroupName $_.ResourceGroupName -Name $_.Name }

# Export VM list σε CSV
Get-AzVM | Select-Object Name, Location, ResourceGroupName |
  Export-Csv -Path "vm-inventory.csv" -NoTypeInformation

# Get Resource Groups με specific tag
Get-AzResourceGroup | Where-Object { $_.Tags.Environment -eq "Production" }
Realistic ScenarioSeptona — M365/Azure Inventory Export με PowerShell

Κατάσταση: Πρέπει να φτιάξεις inventory report: όλα τα Azure VMs, storage accounts και resource groups για EcoVadis compliance. Γνωστό αυτό από τη δουλειά σου!

# Complete Azure Inventory Script
Connect-AzAccount

# VMs
$vms = Get-AzVM | Select-Object `
  Name, Location, ResourceGroupName,
  @{N="Size";E={$_.HardwareProfile.VmSize}},
  @{N="OS";E={$_.StorageProfile.OsDisk.OsType}}

# Storage Accounts
$storage = Get-AzStorageAccount | Select-Object `
  StorageAccountName, ResourceGroupName, Location,
  @{N="SKU";E={$_.Sku.Name}},
  @{N="Kind";E={$_.Kind}}

# Export
$vms     | Export-Csv "azure-vms.csv"     -NoTypeInformation
$storage | Export-Csv "azure-storage.csv" -NoTypeInformation

Αυτό είναι ακριβώς αυτό που έκανες για το Bulgarian tenant inventory project!

Azure CLI (az)

Το Azure CLI είναι cross-platform command-line tool (Python-based). Χρησιμοποιείται ευρέως σε bash scripts, CI/CD pipelines, και Cloud Shell. Η syntax είναι πιο "unix-friendly" από το PowerShell.

Installation

# Windows — winget (recommended)
winget install --exact --id Microsoft.AzureCLI

# macOS
brew install azure-cli

# Ubuntu/Debian
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash

# Verify installation
az --version

# Update
az upgrade

Authentication & Context

# Interactive login
az login

# Login σε specific tenant
az login --tenant your-tenant-id

# Service Principal login (automation)
az login --service-principal \
  --username "app-id" \
  --password "secret" \
  --tenant "tenant-id"

# Show current account/subscription
az account show

# List all subscriptions
az account list --output table

CLI Syntax Structure

Command Pattern
az [group] [subgroup] [command] [--parameters]

# Examples:
az vm create          --resource-group RG-GR --name MyVM ...
az network vnet create --resource-group RG-GR --name MyVNet ...
az storage account create --name mystorage --sku Standard_GRS ...
az role assignment create --role Contributor --assignee user@email.com ...
az policy assignment create --name MyPolicy --policy PolicyDefId ...

Output Formats & Querying

# Output formats: json (default), jsonc, table, tsv, yaml, none
az vm list --output table
az vm list -o tsv                    # Tab-separated — good for scripting
az vm list -o json | python -m json.tool  # Pretty-print JSON

# JMESPath query — extract specific fields
az vm list --query "[].{Name:name, RG:resourceGroup, Location:location}" -o table

# Single value extraction
az vm show --resource-group RG-GR --name SRV-APP-01 \
  --query "hardwareProfile.vmSize" -o tsv

# Filter results
az vm list --query "[?location=='westeurope']" -o table

Azure Cloud Shell

Το Azure Cloud Shell είναι browser-based shell ενσωματωμένο στο Azure Portal. Δεν χρειάζεσαι τίποτα εγκατεστημένο τοπικά — άνοιξε portal, πάτα το shell icon, και έχεις PowerShell ή Bash με Az module/CLI pre-installed.

Χαρακτηριστικά

  • Pre-installed: Az module, Azure CLI, kubectl, terraform, git
  • Persistent storage: 5GB Azure Files share (δωρεάν)
  • Authenticated αυτόματα με portal session
  • Bash ή PowerShell — εναλλαγή οποτεδήποτε
  • Monaco editor (VS Code engine) built-in
  • Upload/download αρχεία

Πώς ανοίγεις

  • Portal: top-right toolbar → shell icon (>>_)
  • URL: shell.azure.com (standalone)
  • VS Code: Azure Account extension
  • Πρώτη χρήση: επιλέγεις Bash ή PowerShell
  • Απαιτεί storage account για persistence (δημιουργείται αυτόματα)
# Στο Cloud Shell (Bash) — τρέχεις CLI απευθείας, χωρίς az login
az vm list -o table

# Στο Cloud Shell (PowerShell) — Connect-AzAccount δεν χρειάζεται
Get-AzVM

# Upload αρχείο και χρησιμοποίησέ το (ARM template deploy)
az deployment group create \
  --resource-group RG-Servers-GR \
  --template-file ~/my-template.json
✅
Exam Tip: Cloud Shell ερωτήσεις είναι rare αλλά εμφανίζονται σε lab tasks. Το key point: Cloud Shell δεν απαιτεί authentication — είσαι ήδη logged in μέσω portal. Και persistent storage — αρχεία στο ~/clouddrive παραμένουν μεταξύ sessions.

Switch Between Subscriptions

Πολύ πρακτικό για scenarios με πολλαπλά subscriptions — όπως Septona GR και BG tenants. Συχνά εμφανίζεται σε exam questions.

PowerShell — Manage Subscriptions

# List όλα τα subscriptions που έχεις access
Get-AzSubscription

# Switch σε specific subscription
Set-AzContext -SubscriptionId "subscription-guid"
# ή με όνομα
Set-AzContext -SubscriptionName "Septona-GR-Production"

# Verify τρέχον subscription
Get-AzContext

# Select subscription κατά login
Connect-AzAccount -SubscriptionId "subscription-guid"

Azure CLI — Manage Subscriptions

# List subscriptions
az account list --output table

# Show current subscription
az account show

# Set default subscription
az account set --subscription "subscription-guid-or-name"
# ή με όνομα
az account set --subscription "Septona-BG-Production"

# Run command σε specific subscription χωρίς να αλλάξεις default
az vm list --subscription "Septona-BG-Production" -o table
Realistic ScenarioMulti-Tenant Operations — GR & BG Subscriptions

Κατάσταση: Η Septona έχει δύο Azure subscriptions — ένα για GR operations και ένα για BG. Πρέπει να τρέξεις script που list-άρει VMs και από τα δύο.

# Script που τρέχει σε multiple subscriptions
$subscriptions = @(
  @{Name="Septona-GR"; Id="gr-subscription-id"},
  @{Name="Septona-BG"; Id="bg-subscription-id"}
)

$allVMs = @()
foreach ($sub in $subscriptions) {
  Set-AzContext -SubscriptionId $sub.Id
  $vms = Get-AzVM | Select-Object Name, Location,
    @{N="Subscription";E={$sub.Name}}
  $allVMs += $vms
}

$allVMs | Export-Csv "all-azure-vms.csv" -NoTypeInformation
Write-Host "Total VMs: $($allVMs.Count)"

Αυτό είναι παρόμοιο με το Bulgarian tenant data export project που έκανες!

Chapter 01

Quiz — Azure Concepts & CLI

◈ Question 01 / Concepts
Ποιο Azure service model σε αφήνει να διαχειρίζεσαι ΜΟΝΟ την εφαρμογή και τα data, ενώ το Azure διαχειρίζεται OS, runtime, scaling;
  • A) IaaS (Infrastructure as a Service)
  • B) PaaS (Platform as a Service)
  • C) SaaS (Software as a Service)
  • D) CaaS (Containers as a Service)
✅ B — PaaS. Στο PaaS, εσύ deploy-άρεις την εφαρμογή (κώδικα, data), και το Azure αναλαμβάνει OS patching, runtime updates, scaling, load balancing. Παράδειγμα: App Service. IaaS = managed VMs, αλλά εσύ κάνεις OS. SaaS = χρησιμοποιείς το software (π.χ. M365).
◈ Question 02 / PowerShell
Θέλεις να κάνεις list όλα τα VMs σε ένα Resource Group με PowerShell. Ποια εντολή χρησιμοποιείς;
  • A) az vm list --resource-group RG-Servers-GR
  • B) Get-AzVirtualMachine -ResourceGroupName "RG-Servers-GR"
  • C) Get-AzVM -ResourceGroupName "RG-Servers-GR"
  • D) List-AzVM -Group "RG-Servers-GR"
✅ C — Get-AzVM -ResourceGroupName "RG-Servers-GR". PowerShell Az module χρησιμοποιεί Get-AzVM (όχι Get-AzVirtualMachine). Option A είναι Azure CLI. Option D δεν υπάρχει — δεν υπάρχει "List-" verb στο Az module.
◈ Question 03 / Azure CLI
Τρέχεις az vm list --output table και θέλεις να δεις μόνο το name και location κάθε VM. Ποιο flag χρησιμοποιείς;
  • A) --filter "name,location"
  • B) --select name location
  • C) --query "[].{Name:name, Location:location}"
  • D) --fields name,location
✅ C — --query με JMESPath expression. Azure CLI χρησιμοποιεί --query με JMESPath syntax για filtering output. Η έκφραση "[].{Name:name, Location:location}" επιλέγει τα πεδία name και location από κάθε element του array.
◈ Question 04 / Hierarchy
Θέλεις να εφαρμόσεις Azure Policy σε όλα τα subscriptions της εταιρείας ταυτόχρονα. Σε ποιο scope την εφαρμόζεις;
  • A) Resource Group
  • B) Subscription
  • C) Management Group
  • D) Tenant Root
✅ C — Management Group. Management Group είναι πάνω από Subscriptions στην ιεραρχία. Policy εφαρμοσμένη σε Management Group κληρονομείται από ΟΛΕΣ τις subscriptions κάτω από αυτό. Resource Group scope = μόνο αυτό το RG. Subscription = μόνο αυτό το subscription.
◈ Question 05 / Cloud Shell
Χρησιμοποιείς Azure Cloud Shell για πρώτη φορά. Τι χρειάζεται να κάνεις πριν τρέξεις az vm list;
  • A) Να εγκαταστήσεις Azure CLI με az install
  • B) Να τρέξεις az login για authentication
  • C) Να επιλέξεις storage account για persistence — τίποτα άλλο
  • D) Να κατεβάσεις τα Az credentials τοπικά
✅ C — Επιλογή storage account. Στο Cloud Shell, Azure CLI είναι ήδη εγκατεστημένο και εσύ είσαι ήδη authenticated μέσω portal session — δεν χρειάζεσαι az login. Η μόνη απαίτηση πρώτης φοράς είναι να δημιουργηθεί storage account για persistent storage.
◈ Question 06 / Switch Subscription
Με Azure CLI, θέλεις να αλλάξεις active subscription χωρίς να ξανακάνεις login. Ποια εντολή;
  • A) az login --subscription "sub-name"
  • B) az account set --subscription "sub-name-or-id"
  • C) az subscription switch --name "sub-name"
  • D) Set-AzContext -SubscriptionName "sub-name"
✅ B — az account set --subscription. az account set αλλάζει το active subscription χωρίς re-login. Δέχεται subscription ID ή name. Option D είναι PowerShell (σωστό για PS αλλά λάθος για CLI). Option A κάνει νέο login.

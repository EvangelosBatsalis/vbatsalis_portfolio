Accounts, Subscriptions & Resource Groups

ConceptΠεριγραφήBilling
Account (Billing Account)Microsoft Customer Agreement / EA — ο "λογαριασμός" πληρωμήςInvoices εδώ
SubscriptionLogical unit resources + billing. Εμπιστεύεται έναν Entra tenant.Costs aggregated per subscription
Resource Group (RG)Logical container — ίδιος lifecycle, region-agnosticΔεν χρεώνεται ξεχωριστά
ResourceActual Azure service — VM, Storage, VNet κλπPer-resource billing

Resource Group Best Practices

  • Same lifecycle: Resources που deploy/delete μαζί → ίδιο RG
  • Region του RG: Metadata location — resources μπορούν να είναι σε άλλες regions
  • One resource, one RG: Resource ανήκει σε ακριβώς ένα RG ανά πάσα στιγμή
  • Move: Μπορείς να μεταφέρεις resources μεταξύ RGs ή subscriptions

Lesson 56 · 7.2

Management Groups

Τα Management Groups είναι containers για subscriptions — επιτρέπουν να εφαρμόζεις policies και RBAC σε πολλαπλά subscriptions ταυτόχρονα.

Hierarchy Example — Septona
Root Management Group (Tenant)
  └── Septona-Root MG
        ├── Production MG
        │     ├── Subscription: Septona-GR-Prod
        │     └── Subscription: Septona-BG-Prod
        ├── Development MG
        │     └── Subscription: Septona-Dev
        └── Sandbox MG
              └── Subscription: Septona-Sandbox
  • Max 6 levels deep (not counting root)
  • Policies/RBAC assigned at MG level inherit to all subscriptions below
  • Each MG/subscription έχει έναν parent (tree structure)
  • Root MG = "Tenant Root Group" — auto-created, all subscriptions are under it
# Create Management Group
az account management-group create \
  --name "Septona-Production" \
  --display-name "Septona Production"

# Move subscription to Management Group
az account management-group subscription add \
  --name "Septona-Production" \
  --subscription "SUBSCRIPTION-ID"

Lesson 49 · 7.3

Resource Locks

Τα Resource Locks προστατεύουν critical resources από τυχαία διαγραφή ή τροποποίηση. Εφαρμόζονται σε subscription, RG, ή individual resource.

🔒 CanNotDelete (Delete Lock)
  • Read resource
  • Modify resource (update settings)
  • Delete resource
🔒 ReadOnly Lock
  • Read resource
  • Modify resource
  • Delete resource
  • listKeys (POST operations)
  • Restart VM (POST)
🎯
ReadOnly Lock Traps:
• ReadOnly lock σε Storage Account → δεν μπορείς να κάνεις listKeys() — POST operation
• ReadOnly lock σε VM → δεν μπορείς να το κάνεις start/stop/restart
• Locks ΔΕΝ κληρονομούνται αυτόματα — πρέπει να τα βάλεις ξεχωριστά
• Lock σε RG ισχύει για ΟΛΑ τα resources μέσα στο RG 
# Create CanNotDelete lock σε critical RG
az lock create \
  --name "DoNotDelete-Production" \
  --resource-group "RG-Production-GR" \
  --lock-type "CanNotDelete" \
  --notes "Production resources - do not delete"

# List locks
az lock list --resource-group "RG-Production-GR"

# Delete lock (πρέπει να το αφαιρέσεις πριν delete resource)
az lock delete \
  --name "DoNotDelete-Production" \
  --resource-group "RG-Production-GR"

# PowerShell
New-AzResourceLock -LockName "NoDeletion" -LockLevel CanNotDelete -ResourceGroupName "RG-Production-GR"

Azure Policy

Το Azure Policy επιτρέπει να ορίζεις και εφαρμόζεις organizational standards στα Azure resources. Ελέγχει ποια resources δημιουργούνται και πώς configurated.

Policy Effects

EffectΤι κάνειUse Case
DenyΜπλοκάρει resource creation/update που παραβιάζει policy"Δεν επιτρέπεται resources εκτός West Europe"
AuditResource δημιουργείται αλλά μαρκάρεται ως non-compliant στο logVisibility χωρίς enforcement
AuditIfNotExistsAudits αν related resource δεν υπάρχει"Αν VM δεν έχει antimalware extension, audit it"
DeployIfNotExistsΑυτόματα deploy related resource αν δεν υπάρχειAuto-deploy monitoring agent σε νέα VMs
AppendΠροσθέτει fields κατά resource creationAuto-add required tags
ModifyΤροποποιεί properties κατά create/updateAuto-add/modify tags

Policy Initiatives (Policy Sets)

Ομαδοποίηση πολλών policies σε ένα set — εκχωρείς το initiative σαν ένα αντικείμενο:

# Assign built-in policy — "Allowed locations"
az policy assignment create \
  --name "Allowed-Locations-GR" \
  --policy "e56962a6-4747-49cd-b67b-bf8b01975c4f" \
  --scope "/subscriptions/SUBSCRIPTION-ID" \
  --params '{"listOfAllowedLocations":{"value":["westeurope","northeurope"]}}'

# Create custom policy definition
az policy definition create \
  --name "require-tags-policy" \
  --rules require-tags.json \
  --mode Indexed

# Check compliance
az policy state list \
  --resource-group "RG-Production-GR" \
  --filter "complianceState eq 'NonCompliant'"

Remediation Tasks

Για policies με DeployIfNotExists ή Modify effect, μπορείς να δημιουργήσεις Remediation Task για να φέρεις existing non-compliant resources σε compliance.

Realistic ScenarioEcoVadis Compliance — Azure Policy για Septona

Κατάσταση: EcoVadis audit απαιτεί: (1) Όλα τα resources να έχουν tags, (2) VMs να έχουν monitoring agent, (3) Storage accounts να χρησιμοποιούν minimum TLS 1.2.

  1. Policy 1 — Require Tags: Effect: Deny — δεν δημιουργείται resource χωρίς tags "Environment", "CostCenter", "Owner"
  2. Policy 2 — Azure Monitor Agent: Effect: DeployIfNotExists — auto-installs monitor agent σε νέα VMs
  3. Policy 3 — TLS 1.2: Effect: Deny — αρνείται storage accounts με minimumTlsVersion < TLS1_2
  4. Group σε Initiative: "Septona-Security-Baseline"
  5. Assign initiative σε subscription scope → ισχύει για GR και BG
  6. Remediation task για existing non-compliant resources

Lesson 53 · 7.5

Tags

Tags = key-value pairs που attach-άρεις σε Azure resources για organization, cost tracking, automation.

🎯
Tags ΔΕΣΜΕΥΤΙΚΟ FACT: Tags ΔΕΝ κληρονομούνται από Resource Group σε resources. Αν βάλεις tag στο RG, τα resources μέσα ΔΕΝ παίρνουν αυτόματα το tag. Χρησιμοποίησε Azure Policy με Append ή Modify effect για auto-tagging.
# Add tags σε resource group
az group update \
  --name "RG-Production-GR" \
  --tags Environment=Production CostCenter=IT-GR Owner=vag@septona.gr

# Add tag σε specific resource
az resource tag \
  --ids "/subscriptions/.../virtualMachines/SRV-APP-01" \
  --tags Environment=Production Tier=Application

# List resources με specific tag
az resource list --tag "Environment=Production" -o table

# Cost analysis by tag (cost management)
az consumption usage list \
  --start-date "2026-01-01" \
  --end-date "2026-03-31"

Lesson 54 · 7.6

Move Resources

Μπορείς να μεταφέρεις resources μεταξύ RGs, subscriptions (ίδιο tenant), ή regions.

Move Constraints

  • Κατά τη μεταφορά, source και destination RG locked — δεν μπορείς να αλλάξεις τίποτα
  • Δεν μπορούν όλα τα resources να μετακινηθούν — ελέγχεις με az resource show --move-validation
  • VNets: Μπορούν να μετακινηθούν αλλά μόνο με ΟΛΑ τα resources που τα χρησιμοποιούν
  • Cross-subscription: Το subscription target πρέπει να εμπιστεύεται τον ίδιο Entra tenant
  • Resource IDs αλλάζουν μετά τη μεταφορά — update hardcoded references
# Move VM από RG-Old σε RG-New
az resource move \
  --destination-group "RG-New" \
  --ids "/subscriptions/.../resourceGroups/RG-Old/providers/Microsoft.Compute/virtualMachines/MyVM"

Cost Management & Budgets

Azure Cost Management σου δίνει visibility και control σε Azure spending.

Key Features

Cost Analysis

  • Breakdown per service
  • Filter by tag, RG, subscription
  • Trends over time
  • Forecast future costs

Budgets

  • Set monthly spending limit
  • Alert at % threshold (e.g. 80%)
  • Email notifications
  • Trigger action groups

Azure Advisor

  • Cost optimization tips
  • "Resize/shutdown idle VMs"
  • Reserved instances recommendations
  • Security, reliability tips

Cost Optimization Strategies

StrategySavingsUse When
Reserved Instances (1 or 3 year)Up to 72%Predictable, steady-state workloads
Azure Hybrid BenefitUp to 40%Existing Windows Server / SQL licenses
Spot VMsUp to 90%Batch jobs, dev/test, fault-tolerant workloads
Dev/Test pricingSignificant on WindowsNon-production environments
Auto-shutdown VMsEliminates idle costDev VMs that don't run 24/7
 
# Create budget με alert στο 80%
az consumption budget create \
  --budget-name "Monthly-IT-Budget" \
  --amount 1000 \
  --time-grain "Monthly" \
  --start-date "2026-04-01" \
  --end-date "2027-03-31" \
  --notifications '[{"enabled":true,"operator":"GreaterThan","threshold":80,"contactEmails":["vag@septona.gr"]}]'

Quiz — Governance

◈ Q01
Βάλεις ReadOnly lock σε ένα storage account. Τι δεν μπορεί να γίνει;
  • A) Διαβάσεις blobs μέσω SAS token
  • B) Κάνεις listKeys() για τα access keys
  • C) Δεις τα properties του storage account
  • D) Download αρχεία με Azure Storage Explorer
✅ B — listKeys(). ReadOnly lock μπλοκάρει POST operations. listKeys() είναι POST. Το storage account είναι readable, αλλά δεν μπορείς να πάρεις τα access keys. Αυτό effectively blocks management-plane access μέσω keys.
◈ Q02
Resource Group έχει tag "Environment=Production". Ένα VM δημιουργείται μέσα στο RG. Ποιο tag έχει το VM;
  • A) Environment=Production (κληρονομεί από RG)
  • B) Κανένα tag (tags δεν κληρονομούνται)
  • C) Εξαρτάται από το VM type
  • D) Environment=Production αν δεν έχεις ορίσει άλλο
✅ B — Κανένα tag. Tags ΔΕΝ κληρονομούνται στο Azure. RG tag δεν μεταφέρεται σε resources. Για auto-tagging χρησιμοποιείς Azure Policy με Append/Modify effect.
◈ Q03
Θέλεις να απαγορεύσεις δημιουργία Azure resources εκτός της region "West Europe" σε ΟΛΑ τα subscriptions. Ποιο scope χρησιμοποιείς;
  • A) Assign policy σε κάθε subscription ξεχωριστά
  • B) Assign policy σε Management Group που περιέχει όλα τα subscriptions
  • C) Assign policy σε Resource Group
  • D) Χρησιμοποίησε Resource Lock
✅ B — Management Group scope. Policy σε MG ισχύει για ΟΛΑ τα subscriptions κάτω από αυτό μέσω inheritance. Ξεχωριστό assignment σε κάθε subscription = error-prone και δεν covers future subscriptions.
◈ Q04
Ποιο policy effect αυτόματα deploy-άρει related resource (π.χ. diagnostic settings) αν δεν υπάρχει;
  • A) Deny
  • B) Audit
  • C) DeployIfNotExists
  • D) Append
✅ C — DeployIfNotExists. Auto-deploys related resource αν condition δεν ικανοποιείται. Χρειάζεται managed identity για το policy assignment για να κάνει deployments. Audit = μόνο logs. Deny = μπλοκάρει. Append = προσθέτει properties.

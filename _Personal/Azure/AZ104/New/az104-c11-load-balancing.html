Configure Load Balancing

Azure Load Balancer (L4) distributes TCP/UDP traffic. Application Gateway (L7) adds URL-based routing, WAF, SSL termination. Understand when to use each and the key differences.

Standard LB is CLOSED by default. After creating Standard LB, traffic still blocked until you add NSG rule to allow it. Basic LB = open. This is a VERY common exam trap.

LB Components

  • Frontend IP: Public or private IP that clients connect to
  • Backend pool: VMs or VMSS instances receiving traffic
  • Health probe: Checks VM health (HTTP GET / TCP connect). Unhealthy = removed from pool.
  • Load balancing rule: Maps frontend IP:port → backend pool:port
  • NAT rule: Forward specific port to specific VM (for RDP, SSH)
  • Outbound rule: Configure SNAT for outbound internet connectivity

Setup Load Balancer

# Create Standard Public LB
az network lb create   --resource-group RG-Network-GR   --name LB-WebServers   --sku Standard   --public-ip-address PIP-LB-WebServers   --frontend-ip-name FE-Web   --backend-pool-name BE-WebPool

# Add health probe (HTTP on port 80)
az network lb probe create   --resource-group RG-Network-GR   --lb-name LB-WebServers   --name HealthProbe-HTTP   --protocol Http   --port 80   --path /health

# Add LB rule: port 80 → backend port 80
az network lb rule create   --resource-group RG-Network-GR   --lb-name LB-WebServers   --name LBRule-HTTP   --protocol Tcp   --frontend-port 80   --backend-port 80   --frontend-ip-name FE-Web   --backend-pool-name BE-WebPool   --probe-name HealthProbe-HTTP

# Add VM NIC to backend pool
az network nic ip-config update   --resource-group RG-Servers-GR   --nic-name SRV-WEB-01-NIC   --name ipconfig1   --lb-name LB-WebServers   --lb-address-pools BE-WebPool

Lesson 156 · 21.4

Application Gateway

Application Gateway = L7 load balancer. Understands HTTP/HTTPS — can route based on URL path, hostname, or headers.

Key Features

  • URL-based routing: /api/* → API servers, /images/* → image servers
  • Host-based routing: api.septona.gr → API pool, www.septona.gr → web pool
  • SSL termination: Decrypts HTTPS at gateway — backend VMs get plain HTTP
  • Cookie-based session affinity: Same user → same backend VM
  • WAF (Web Application Firewall): OWASP rule sets, protect against SQLi, XSS
  • Rewrite rules: Modify HTTP headers, URLs on the fly
  • Autoscaling (v2 SKU): Scale based on traffic load

AppGW SKUs

SKUFeatures
Standard v1Basic L7. Fixed capacity. Legacy.
Standard v2 CurrentAutoscale, Zone redundancy, 99.95% SLA

When to use what:
Need URL path routing or WAF → Application Gateway
Need global DNS-based routing/failover → Traffic Manager
Need global CDN + WAF → Azure Front Door
TCP load balancing, simple, fast → Load Balancer

Quiz

◈ Q01
Μετά την δημιουργία Standard Load Balancer, clients δεν μπορούν να συνδεθούν στα VMs. Τι λείπει;
  • A) Health probe config
  • B) NSG rule να allow inbound traffic στα VMs
  • C) Backend pool members
  • D) Public IP στα VMs
✅ B — NSG rule. Standard LB is closed by default — all inbound blocked unless NSG on VMs/subnet allows it. Basic LB is open. Most common exam trap!
◈ Q02
E-commerce site: /api/* → API servers, /images/* → CDN servers, /shop/* → web servers. Ποιο Azure service;
  • A) Azure Load Balancer
  • B) Azure Traffic Manager
  • C) Azure Application Gateway
  • D) Azure Front Door (Global)
✅ C — Application Gateway. URL path-based routing = L7 = Application Gateway. Load Balancer is L4 (no URL awareness). Traffic Manager = DNS-based global. Front Door = global CDN.
